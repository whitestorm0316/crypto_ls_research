## 二、未来视审计

### 2.1 审计方法（为什么这次不是"看代码觉得对"）

仓库自带 `tests/test_no_lookahead.py`（9 个测试，本轮 **9 passed**），但它跑在**合成数据**上。
合成数据与真实面板之间存在缝隙，所以本轮补了**独立于测试的真实数据实验**：

`scripts/audit_lookahead_realdata.py`
1. 在真实面板（50,319 bars × 161 合约）上跑一次推荐配置回测 → 基线；
2. 把**第 t0 根 bar 及其之后的一切**破坏（价格 ×U[0.2,5]、成交额 ×U[1e3,1e6]、资金费 ×7−0.001）；
3. 断言**所有 t0 之前的决策**逐位不变：选币名单、score 矩阵、`net_ret[:t0-1]`；
4. 断言**突变确实咬住了**（t0 之后必须变）——否则第 3 步是空的。

第 4 步是关键：**没有它，一个"什么都没算"的实现也能通过。**

### 2.2 结果

| t0 位置 | 时间 | `net_ret[:t0]` 最大差异 | t0 之后差异 | 判定 |
|---|---|---|---|---|
| 15% | 2021-11-11 | **0.000e+00** | 1.221e+00 | PASS |
| 30% | 2022-09-21 | **0.000e+00** | 9.568e-01 | PASS |
| 55% | 2024-02-28 | **0.000e+00** | 1.806e+00 | PASS |
| 70% | 2025-01-07 | **0.000e+00** | 9.959e-01 | PASS |
| 85% | 2025-11-18 | **0.000e+00** | 7.741e-01 | PASS |

**逐位相同（不是"接近"），且每个点都确认突变生效。** 375 个 t0 前的调仓点，选币名单 100% 一致。

### 2.3 审计途中排掉的一个假阳性（值得记录）

第一次运行报 FAIL，`net_ret[:t0]` 差异 **7.697e-08**。这是**我的审计脚本**的锅，不是策略的：我在突变时把面板转成了 float64，而引擎内部存的是 float32（eps ≈ 1.2e-7）。
→ 修正为**保持原 dtype** 后，差异从 7.7e-08 变成 **0.000e+00**。
**教训**：未来视实验里 dtype 必须对齐，否则真实信号（1e-7 级）会被 float32 表示误差淹没，看起来像"抓到了未来视"。

### 2.4 逐层核查（代码路径）

| 层 | 实现 | 判定 |
|---|---|---|
| 因子引擎 | 全 `rolling` + `shift(正数)`，无 `center=True`、无 `shift(-k)`、无全样本统计量 | 干净 |
| 横截面 z-score | `zscore(x)` 只吃**单 bar 的 (N,) 向量**；`mu/sd` 来自本 bar | 干净 |
| 因子中性化 | 单 bar 截面 OLS，且仅在 `neutralize=True` 时启用（默认关） | 干净 |
| PIT universe | `age >= min_history`、trailing ADV 滚动均值、rank 每调仓重算 | 干净 |
| 执行价 | `dec_idx[i] = d`，成交在 `t = d+1`；`next_open` 取下一根 bar 开盘 | 干净 |
| beta | `returns.rolling(w).cov(bench)`，无 center | 干净 |
| BTC regime / vol target | `btc_close.shift(mom_bars)`、`rolling(...).std()` | 干净 |
| 风控 overlay | `regime_scale`/`btc_vol_scale`/`vol_target_scale`/`dd_scale` 全用 bar d 及之前 | 干净 |
| warmup | `dec_idx` 从 `warmup` 起，`warmup = max(各因子窗口 + 2)` | 干净 |

### 2.5 真正的未来视：参数选择（**这是问题所在**）

`analysis/walkforward.py` 的两个检验**实现是正确的**：
- `fold_stability`：同参数切子区间 → 无未来视（不拟合）；
- `walk_forward_selection`：**train 选优、test 报告** → 正确切分。

**但 MEMORY 已明确记载、本轮复核确认：对外交付的推荐配置是在全样本上 OFAT 选出来的。**
具体证据（来自既有权威记录）：
- `hitrate_days` 的全样本最优**完全由 2026 决定**（2021–25 的 argmax 是 21 日）；
- 2026 用 **12.8% 的时间贡献 31.9% 的累计收益**；
- 「宽度自适应 cap」看着该采纳，但 2026 Δ = **−0.976**。

**结论**：这不是代码 bug，是**流程性质的过拟合**，任何单元测试都抓不到。
**对外预期必须用 2021–2025 分窗：CAGR 19.00% / Sharpe 1.60 / MDD −12.72%**，不得再用全样本 1.937。

## 三、实盘可跑性评估

### 3.1 重大认知更新（我此前的记录已过时）

|---|---|---|

| `minSz`/`lotSz` | 「`instruments.parquet` 缺」 | **`data_cache/meta/swap_specs.json` 已补，477 个 USDT swap 零缺失** |
| 风控限额 | 30000 / 2500 | 界面持久化值实为 **50000 / 10000**（代码默认 5000 / 1000） |
| `execution/__init__.py` | 「空文件」 | 37 行 |

**"平台侧几乎为零"这个结论已经不成立，必须撤回。**

### 3.2 执行层已实现的能力（实测清单）

- **签名**：OKX v5 规范，`pre_sign = ts + METHOD + path + body`，query 只编码一次（防 50113）。
- **幂等下单**：`clOrdId` 确定性生成；**下单不盲重试**——传输失败抛 `AmbiguousError`，要求对账而非重发。
- **对账**：`reconcile()` 拉 `order_by_clordid` 更新订单状态 + 拉 `fills` 按 `tradeId` 去重。
- **并发防护**：`rebalance_lock` 文件锁（PID 存活 + TTL 接管），防"两个 actor 各发一次完整订单 → 仓位翻倍"。
- **目标书幂等**：`build_plan(current_sz → target_weights)` 算差量，重跑同一目标书不会重复建仓。
- **风控闸门**：`check_plan` 在**发单前**拦截（单笔上限、gross 上限、杠杆、ADV 参与率、允许标的）。
- **kill switch**：文件实现（survives 崩溃/卡死的 UI），`fail closed`——解除失败时仍保持禁交易。
- **紧急平仓**：`flatten()`（dry-run 默认）。
- **目标书对齐回测**：`turnover_budget` 强制对齐（不设会跑 **2.2×** 已验证敞口）。
- **demo 链路实测**：`preview` 全链路跑通，`blocked: false`，信号就绪，风控正确识别模拟盘缺 7 个腿。
- **测试**：实盘相关 5 个测试文件 **228 passed / 1 skipped**；全套 **347 passed / 1 skipped**。

### 3.3 状态与缺口

**已就位**：
- `demo` 凭证已配置（key_hint `7d00…e8f5`，source=file）；
- `live` 凭证**未配置** → **物理上不可能误发实盘单**（这是好事）；
- 模拟盘账户 `pos_mode=long_short_mode`。

**真实缺口**（按严重度排序）：

1. **成交假设从未被真实校准**（最重要）。
   净 Sharpe 1.937 目前只是"模型输出"：taker 5bps = OKX LV1、`passive_fill_ratio=0.0`（100% taker）、**薄池半价差 3.0bps 是分档常数不是实测报价**（91% 成交名次在 ADV<$25M 档）。
   → **费用层有安全边际（fee×3 仍 1.74），但成交价与成交率无法用历史数据回答。**

2. **实盘资金费不进本地归因**。
   净值从 OKX 拉取**已含**资金费（交易所自动结算，不会算错），但本地 `equity.jsonl` 的 `gross/costs/funding` 分解**不含实盘资金费** → 归因报表缺一块。净值准、归因不全。

3. **强平/ADL 路径无实战证据**。
   样本内强平触发 **0 次** → 该分支只有单测，没有真实成交验证。

4. **小资金颗粒度**。
   `min_sz × ct_val × price` 与本金无关（池内中位约 $1、最大 $15.39）。$70 下 13 个有效名字只剩 9 个。**门槛：物理 $70 / 可用 $500 / 接近回测口径 $2000–5000。**

5. **风控限额是用户放宽后的值**（50000/10000）。
   代码默认（5000/1000）才是"首次实盘的保守值"。**上实盘前必须重新评估这组数字**——它是绝对风控闸门，不是策略参数。

6. **模型外偏差未建模**：强平罚款/ADL、出入金费、税、模型外滑点（方向都更差）；大户返佣（更好）。

## 四、落地建议

**不要跳过影子盘。**

- **S0 补欠账**：排除 2026 重跑 + 离散度条件归因 + 第三方退市清单。
- **S1 影子盘 4–8 周（只记不下）** ← **下一步就该做这个**。用真实盘口/成交记录校准第 3.3 节的缺口 1。目前 demo 链路已通，能立刻开始。
- **S2 小资金 $50k–$100k**（硬风控 / 持仓对账 / 幂等下单三者缺一不进）。
- **S3 扩规模**。

**跳过 S1 直接上 S2 是最贵的可能错误**——研究侧的 Sharpe 是模型输出，成交侧从未被现实检验。

**对外口径**：CAGR 19.00% / Sharpe 1.60（2021–25 分窗），回撤按 **−20%** 留缓冲（MDD −12.72% 整个落在 2025，是正常年份发生的）。
