# 策略优化路线图

> 面向 `Crypto Futures Liquidity Flow Trend — Cross-Sectional Market-Neutral Strategy`
> 基准：`tuned` 配置（3d 调仓 + 20% 日换手预算）Sharpe **1.279**、CAGR 14.36%、MDD −9.49%
> 所有数字均有 `artifacts/` 下的机器可读产物支撑，可复算。

## 0. 优化前必须先接受的两条纪律

**纪律一：先分清「修 bug」「调参数」「改逻辑」三类动作。**
本项目的经验是——**最大的两次收益都来自修 bug 式的发现，而不是调参**：

| 类型 | 动作 | 增益 | 性质 |
|---|---|---|---|
| 实现参数 | 1d→3d 调仓 + 50%→20% 预算 | 0.588 → **1.279**（+117%） | 修配置 |
| 实现偏差 | 修复 sizing 退化（见 §2.2） | 1.279 → **1.378**（+7.7%） | **修 bug** |
| 逻辑 | 因子集瘦身（见 §2.3） | 1.279 → **1.549**（+21%） | 改逻辑 |

**纪律二：不要调 `min_abs_score`。** 它是全项目最像过拟合的一个参数：

| `min_abs_score` | 0.0 | 0.25 | **0.5** | 0.75 | 1.0 |
|---|---|---|---|---|---|
| Sharpe | 0.588 | 0.591 | **1.116** | **0.493** | 0.892 |

0.5 处的峰值是两侧的 1.9–2.3 倍，**这是 §40 明确警告的「孤峰热格」形态**，
不是平台。它之所以敏感，是因为 Top-K 在 10–22 个名字的池子里几乎不 binding
（`pit_topn=100` 与 `min_avg_amount_usd=$3M` 才是真正卡池子的门槛），
于是**硬阈值成了唯一的选择开关**，而离散选择天然不稳定。**保持 0.0，让权重连续表达观点。**

## 2. Tier 1 —— 已验证 / 低风险

### 2.1 换手预算与调仓频率（已做，作为新基线）

| 日换手预算 | Sharpe | CAGR | MDD |
|---|---|---|---|
| 10% | **1.685** | 22.39% | −8.55% |
| 20% | 1.614 | 29.23% | −13.39% |
| **50%（规格默认）** | **0.588** | 7.73% | −24.73% |
| 不限 | 0.603 | 7.94% | −26.82% |

调仓频率同理：1h 净 Sharpe **0.065**（毛 1.351），3d **1.244**，7d 1.009。
**高频调仓纯粹在烧手续费**，与 IC 衰减（8 天未见顶）完全一致。

**待办**：`tuned` 用的是 20% 预算；**10% 预算在默认调仓下 Sharpe 更高（1.685）**。
应补测「**10% 预算 × 3d 调仓**」这一组合——这是唯一一个尚未交叉验证过的高价值点。

### 2.2 修复 sizing 退化 —— 这是本路线图**性价比最高**的一项

**问题**：`portfolio/construct.py:118`

```python
if cap * n <= 1.0 + 1e-12:
    return np.full(n, 1.0 / n)     # 静默退化为等权
```

规格默认 `top_k = 10` + `max_weight_per_instrument = 0.10`，于是 `cap × n = 1.0`
**恰好命中这一分支**。实测（直接调用 `inverse_vol_weights`）：

```
K=10 cap=0.05 -> 不同权重个数= 1  max=0.1000   (cap*n=0.50)   <- 等权
K=10 cap=0.10 -> 不同权重个数= 1  max=0.1000   (cap*n=1.00)   <- 等权（规格默认）
K=10 cap=0.15 -> 不同权重个数= 7  max=0.1500   (cap*n=1.50)
K=10 cap=0.20 -> 不同权重个数=10  max=0.2000   (cap*n=2.00)   <- 真逆波动率
```

**结论：规格要求的 `w_i ∝ |score_i| × 1/vol_i` 在本报告的全部 headline 结果里从未生效，
实际跑的是等权。** 端到端验证：`cap=0.10` 与显式 `vol_weight_power=0, score_weight_power=0`
的结果**逐字节相同**（Sharpe 同为 1.279）。

**修复方式（二选一）**：
- 把 `max_weight_per_instrument` 提到 `> 1/top_k`（K=10 时取 0.20）；
- 或在 `cap * n <= 1` 时不退化为等权，而是**明确报错/告警**（当前是静默的，这才是真正的问题）。

**实测增益**：

| 配置 | Sharpe | CAGR | MDD |
|---|---|---|---|
| cap=0.10（等权，现状） | 1.279 | 14.36% | −9.49% |
| cap=0.15 | 1.239 | 14.19% | −11.41% |
| **cap=0.20（真逆波动率）** | **1.378** | **16.65%** | −12.25% |
| cap=0.40 | 1.317 | 16.35% | −13.75% |

**注意代价**：MDD 从 −9.49% 恶化到 −12.25%，且 cap 0.15→0.20→0.40 非单调
（1.239 / 1.378 / 1.317）。所以**取 0.20 是"启用该机制"而非"调到最优"**，
这个区别很重要：不要因为 0.20 恰好最高就认为它是最优值。

### 2.3 因子集瘦身 —— 增益最大、最符合 §40 原则

在**推荐参数**下重跑 15 个子集消融（`artifacts/tuned_abl/`）：

| 因子组合 | Sharpe（推荐 3d/20%） | CAGR | MDD |
|---|---|---|---|
| **range_pos + hitrate** | **1.549** | 17.27% | −11.36% |
| hitrate + momentum + range_pos | 1.374 | 15.14% | −10.38% |
| range_pos（单独） | 1.360 | 14.81% | −10.29% |
| **四因子全用（规格默认）** | **1.279** | 14.36% | −9.49% |
| hitrate（单独） | 1.202 | 12.36% | −9.63% |
| momentum（单独） | 1.115 | 11.85% | −11.02% |
| **flow（单独）** | **0.542** | 5.54% | −18.29% |

**重要更正**：默认参数下 `flow` 单独 −0.040、`hitrate` 单独 −0.344，看起来像"无效因子"；
换成推荐参数后分别变成 **+0.542 / +1.202**。**这两个数字的负值完全是高频换手 + 高成本
造成的，不是因子本身的属性。** 子集 Sharpe 的离散区间也从 `[−0.344, 1.163]` 收窄到
`[0.542, 1.549]` —— 参数对了之后，**因子选择退化为二阶问题**。

**推荐**：`range_pos + hitrate`。**注意这会增加自由度（因子数从 4 降到 2 是在减，
但"选哪 2 个"本身是一次选择）**，所以必须用走向前验证，不能只看全样本。
保守替代：`hitrate + momentum + range_pos`（1.374）。

### 2.4 执行价：`next_open` → `next_close`

| 执行模型 | Sharpe | CAGR |
|---|---|---|
| **next_open（现状）** | 0.588 | 7.73% |
| next_vwap | 0.574 | 8.82% |
| next_twap | 0.595 | 9.49% |
| **next_close** | **0.660** | **9.72%** |

`next_close` 比 `next_open` 高 **+12%**，且**这个方向与 §3.2 的短周期反转证据一致**：
既然分数在 4h 尺度上是"反的"，那么**越晚成交越好**——早成交会撞上短周期反转的错误一侧。

**这是零模型风险的一行配置改动**（`next_close` 仍是完全 PIT 的：在 bar d+1 收盘成交，
用 px[d+2] 盯市）。**但必须在 tuned 参数下复测**——现有对比只在默认参数下做过。

### 2.5 剔除 34 个代币化股票/商品合约

池子里 161 个合约有 **34 个是代币化股票/商品/ETF**（NVDA、TSLA、GOOGL、META、MSTR、MU、
QQQ、SOXL、XAU 黄金、XAG 白银、CL 原油、BZ 布伦特…），其中 **10 个被实际交易**，

- 它们的资金费在币安无对应合约，正是 `median_proxy` 组集中的地方。

## 3. Tier 2 —— 需要实验

### 3.1 因子中性化（brief §38 的遗漏项）

brief §38 的执行流程明确列了 **"Factor Neutralization"** 这一步（在 Factor IC 与 Score 之间），
但代码里**从未实现**——`signals/cross_section.py::composite_score` 只是 z-score 的加权平均。

**为什么它现在值得做**：`momentum ↔ range_pos` 相关系数 **0.710**。
复合分里这两项在**重复计票**同一个方向，而 `flow` 只是被稀释。
正交化（对分数做横截面回归、取残差）能让每个因子只贡献它的**独立部分**。

**做法**：`z_resid = z_f - β·z_other`（横截面逐 bar 回归，完全 PIT），再复合。
**先做实验再决定**：如果正交化后的 `momentum` 残差仍然无效，
那就直接采纳 §2.3 的"砍掉 momentum"更简单。

### 3.2 多周期复合：短周期反转 + 长周期趋势（潜力最大）

逐因子 IC 呈现一个**清晰的符号翻转**，全部横截面、全部 PIT：

| 因子 | 4h IC (t) | 7d IC (t) |
|---|---|---|
| range_pos | **−0.0218 (−3.07)** | **+0.0448 (+6.39)** |
| momentum | **−0.0241 (−3.41)** | +0.0230 (+3.35) |
| hitrate | +0.0014 (0.22) | +0.0426 (+6.38) |
| flow | −0.0059 (−0.85) | +0.0195 (+2.83) |

**4h 处显著为负、7d 处显著为正 —— 这是两个不同的效应，不是噪声。**
含义：**这个分数在几天尺度是趋势信号，在几小时尺度是反转信号。**

两条利用路径：
- **独立的反转 book**（4h 内做分数的反向），与现有 3d 趋势 book 组合。
  两者相关性可能很低 → 组合 Sharpe 有实质提升空间；
- **耐心成交**：既然短周期是反的，就用更被动的执行（限价单 / 跨数小时 TWAP），
  而不是在下一根 open 立即市价吃单。这与 §2.4 的 `next_close` 证据互相印证。

### 3.3 波动率 regime 门控 —— 潜力最大，风险也最高

现有 regime 覆盖很薄：只有「BTC 20d 动量 < 0 → gross × 0.55」。
而分层归因显示**波动率维度的分层效果远强于趋势维度**：

| 维度 | 状态 | Sharpe | 对总收益贡献 |
|---|---|---|---|
| 波动率 | LowVol | **0.894** | +0.317 |
| 波动率 | MidVol | 0.195 | +0.128 |
| 波动率 | **HighVol** | **0.158** | +0.036 |
| BTC 趋势 | BTC_Strong | 0.840 | +0.466 |
| BTC 趋势 | **BTC_Flat** | **−0.051** | −0.021 |
| 趋势 | Bull | 0.568 | +0.335 |
| 趋势 | **Bear** | **0.079** | +0.031 |

**低波动期 Sharpe 是高波动期的 5.7 倍**——若能在高波动期降低敞口，理论增益很大。

**为什么风险最高**：
- 在**同一个样本**上挑 regime 规则，极易过拟合（状态划分本身就是自由度）；
- 状态必须在 t 时刻可观测（用 trailing realized vol 可以，用同期 vol 就是未来函数）；
- 高波动期样本量小（HighVol 仅 5,364 bars / 1,869 days）。

**验证纪律**：必须在**走向前框架内**选 regime 阈值，报告每折的 regime 参数是否稳定。
**如果阈值在四折之间漂移，就说明它是拟合出来的，不是真的。**

### 3.4 资金费感知的选币

- 资金费真实覆盖率只有 **38/162**；其余 124 个用横截面中位数代理，**占换手 61.5%**；
- 但 book 是**净收取**方（+0.58%/年），说明「多空两侧的资金费互相抵消后仍有余量」；
- **可做的事**：在复合分里加一个**资金费倾斜项**（偏向收取方、避开极端付费的名字），
  或对 `|funding|` 超过某分位的名字降权。

**先修数据**：88 个名字失败的原因是币安限流（237 请求 ÷ 38 ≈ 6 页，正确；
按 126 算只有 1.9 页，不可能）。**加退避重试即可补齐**，成本极低，收益是让这一项
从"代理值"变成"实测值"。

## 7. 最后一条，也是最重要的一条

**本项目最大的教训出现在写报告之后**：因子消融的结论（`flow` 无效、`hitrate` 单独最差）
在换成推荐参数后**几乎完全反转**（−0.040 → +0.542、−0.344 → +1.202）。

所以优化时的正确姿势是：

> **任何"某个因子/某个参数无效"的结论，都必须先问一句：
> 这是它的属性，还是当前实现参数的产物？**

调参之前先修 bug，修 bug 之前先确认你没有在测一个根本没生效的机制
（§2.2 的 sizing 就是"看起来在跑、其实静默退化"的典型）。
