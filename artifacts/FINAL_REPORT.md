# 1. Executive Summary

## 1.1 是否存在统计意义上的 Alpha 证据？

**存在，但强度有限，且被交易成本大幅侵蚀。**

三条独立证据：

| 证据 | 结果 | 判断 |
|---|---|---|
| 横截面置换检验（200 次） | p = 0.005 | 通过 |
| 随机打分检验（200 次） | p = 0.005 | 通过 |
| 分块打乱检验（30 次） | p = 0.032 | 通过 |
| Rank IC @ 7 天 | +0.0325（t = 4.69） | 显著为正 |
| Rank IC @ 4 小时 | −0.0227（t = −3.20） | 显著为**负** |
| 38 组参数 OFAT | 正收益占比 1.0（全部为正） | 通过 |
| 三个二维参数网格 | 全部判定 `plateau` | 通过（无孤峰） |

**策略在三个零假设下都跑赢了全部随机基准**（这是 §39 的强制声明项），并且它在短周期上是**反向**的、在长周期上才是正向的——这个"信号很慢"的结论同时解释了为什么高频调仓会亏钱。

## 1.2 但经济意义不足（在规格默认参数下）

| 指标 | 值 |
|---|---|
| CAGR | **7.73%** |
| 年化波动 | 14.24% |
| **Sharpe** | **0.588** |
| 最大回撤 | **−24.73%** |
| **最大回撤持续期** | **1,652 天（约 4.5 年）** |
| 毛 Sharpe（无任何成本） | 1.178 |
| 交易成本拖累 | **8.98%/年** |

**净 Sharpe 只有毛 Sharpe 的一半。** 最大回撤持续 1652 天意味着：从 2022-02-14 到 2025-07-28，**你几乎整个样本期都在水下**。

## 1.3 真正的问题不是"有没有 alpha"

规格默认参数**恰好落在一个局部最差点**上。两处参数改动就能把它变成可用的策略：

| 配置 | Sharpe | CAGR | 年化波动 | 最大回撤 | 回撤持续期 | 年换手 | 成本拖累 |
|---|---|---|---|---|---|---|---|
| `baseline`（规格默认） | 0.588 | 7.73% | 14.24% | −24.73% | 1,652 天 | 97.2× | 8.98%/年 |
| **`tuned`（3d 调仓 + 20% 换手预算）** | **1.279** | **14.36%** | **10.92%** | **−9.49%** | **270 天** | **23.9×** | **2.05%/年** |

`tuned` 配置下**每一年都是正收益**（Sharpe 0.557 / 0.988 / 1.202 / 0.929 / 2.649 / 1.410），
OOS 四折 test Sharpe **全部 ≥ 0.93**（1.202 / 0.929 / 2.649 / 1.410）。
**结论：毁掉绩效的是默认换手设置，不是 alpha 本身。** 两处参数改动使 Sharpe 提升 **117%**、
最大回撤缩小 **62%**、回撤持续期缩短 **84%**、成本拖累下降 **77%**。

> 需要同时注意的代价：`tuned` 的平均 |β| 从 0.0086 升到 **0.0272**（3d 调仓下 beta 对冲更新更慢），
> 但绝对水平仍接近中性。另外多头腿贡献 0.7329、空头腿 0.1619 → **收益更偏向多头腿**，
> 这恰好放大了 §3.4 的退市偏差方向（高估多头），是需要警惕的组合。

## 1.4 必须同时知道的坏消息

1. **策略命名来源的 Flow 是最弱的因子 —— 但"最弱"不等于"无效"。** 它单独在
   规格默认参数下 Sharpe = −0.040，在推荐参数下 **+0.542**。把负值直接解读成
   "因子无效"是**把实现参数问题误诊成因子问题**（详见 §4.5 的更正）。
   去掉它确有提升，但幅度是 +7.4%，不是"绩效翻倍"。
2. **表现最好的因子与策略叙事无关**：`range_pos + hitrate` 在推荐参数下 1.549，
   四因子全用 1.279。**加因子是在减分**，但幅度是 +21%（不是默认参数下看到的 +98%）。
3. **业绩极度集中在 2021 和 2026**：2022 Sharpe −1.264，2023–2025 基本持平。
4. **SOL 单一币贡献 41.1% 的净 PnL**，前 5 名合计超过 100%。
5. **退市/生存偏差不可消除**（OKX 对已下架合约返回 `51001`）。
6. **可交易池只有约 10–22 个名字**，Top10+Top10 几乎等于全池。

## 1.5 绝不使用的表述

本报告不使用"稳赚""必赚""确定有效"。所有结论都附带样本区间、参数位置与失效条件。
**这些数字是研究结论，不是投资建议。**

# 2. Strategy Definition

## 2.1 Universe（点对点 PIT 池）

```
每根决策 bar d，逐个合约判定：
  (1) 上市门槛：close[d] 有效且 > 0（首个有效 bar 起才可用）
  (2) 年龄门槛：age_bars ≥ min_history_days × bars_per_day
  (3) 流动性门槛：trailing liq_window_days 平均成交额 ≥ min_avg_amount_usd
  (4) 排名门槛：按该 trailing 流动性取 TopN
```

**关键实现事实**：上市判定使用**首个有效 K 线**（`first_valid`），不是 `list_dt` 字段。
`list_dt` 是派生字段（`store.py:8` 明确定义为"首个有效 close 的 bar"），两者在构造上一致。
这条契约已由 `test_list_dt_is_a_derived_mirror_of_the_first_valid_bar` 守住。

- 流动性均值为**滚动**均值 → 未来成交额无法进入
- 排名每个调仓 bar 重算
- `mom/flow/range/hitrate` 全部只使用 ≤ d 的数据

## 2.2 Factors（4 个横截面因子）

| 因子 | 公式 | 经济含义 |
|---|---|---|
| **Momentum** | `mom_raw / vol` | 波动率调整后的趋势 |
| **Flow** | `short_amt / long_amt` | 主动卖 / 主动买（流动性流向） |
| **Range Position** | `clip((close − range_low) / (range_high − range_low), 0, 1)` | 区间内相对位置 |
| **Hit Rate** | 过去 N 根上涨 bar 占比 | 上涨持续性 |

波动率：`_ann_vol(logret)`，其中 `logret = log(close.where(close > 0)).diff()`。
**`vol == 0` 被替换为 NaN**（`vol.replace(0.0, np.nan)`），绝不产生 `1/0`。

## 2.3 Score

```
1. 仅在 PIT 池内做横截面标准化：z = (x − median) / (1.4826 × MAD)
2. MAD winsorize（mad_k）、百分位截断（pct_clip）、score clip ±4
3. 复合分 = 加权平均，默认权重 momentum 1.00 / flow 0.40 / range 0.30 / hitrate 0.20
```

**标准化只在池内进行** —— 池外一律 NaN，不参与截面统计。

## 2.4 Portfolio

```
1. 选 Top-K 多（分数最高）与 Top-K 空（分数最低），|score| ≥ min_abs_score
2. 持仓稳定性：hold_thresh 缓冲 + 每期最多替换 n_drop 个
3. 权重：w_i ∝ |score_i| × (1/vol_i)    每侧独立归一化
4. 单标的权重上限 max_weight_per_instrument，超限后迭代再归一化（water-filling）
```

`1/vol` 的守卫（`portfolio/construct.py:101`）：
```python
v = np.where(np.isfinite(v) & (v > 0), v, np.nan)
if np.isnan(v).all(): ...   # 全部缺失 -> 等权
v = np.where(np.isnan(v), np.nanmedian(v), v)   # 个别缺失 -> 中位数
```
**`vol == 0` 不可能产生无穷权重。**

> ⚠️ **重要实现事实（后补发现，见 §13.2）**：`construct.py:118` 在 `cap × n ≤ 1` 时
> **退化为等权**并静默丢弃 `|score|/vol` 加权。规格默认 `top_k = 10` + `cap = 0.10`
> 恰好满足 `cap × n = 1.0` → **本报告的 headline 结果实际是等权，而非逆波动率加权**。
> 实测：`K=10, cap=0.10` 时每侧权重恒为 `0.1`（不同取值个数 = 1）；
> 把 cap 提到 `0.20` 才启用真正的 water-filling。该退化使 Sharpe 少约 7.7%。
> 这是**规格与实现之间的偏差**，不是调参问题。

## 2.5 Beta Neutral（两种方法，对比）

- **A 法（毛敞口对齐 / gross-matched）**：多头毛敞口 = 空头毛敞口
- **B 法（真 beta 中性）**：解 `k = β_u / β_v`，调整两侧毛敞口使净 beta ≈ 0

| 方法 | CAGR | Sharpe | 平均\|β\| |
|---|---|---|---|
| A（毛敞口对齐） | 17.67% | 0.976 | **0.0666** |
| **B（真中性，采用）** | 7.73% | 0.588 | **0.0086** |

**A 法多出来的 Sharpe 是残留 beta，不是 alpha。** 本策略采用 **B 法**（平均 |β| = 0.0086）。

## 2.6 Risk Management（分层）

```
市场状态叠加    : BTC 20 日动量为负 → 毛敞口 × 0.55
波动率目标      : clip(target/realized, min_gross=0.3, max_gross=2.0)
回撤阶梯        : <10% 正常；10–15% ×0.75；15–20% ×0.5；>20% 停止开新仓
                  （带反锁死下限，避免永久停机）
单标的限制      : 权重上限 / ADV 参与率上限 5% / 强平距离 ≥ 3×ATR
```

## 2.7 Execution

- 信号在 bar d 的收盘计算 → 在 **d+1** 的 `next_open` 成交（**信号 / 下单 / 成交三个时点严格分离**）
- 成交模型对比（见 §6.5）：`next_open` / `next_vwap` / `next_twap` / `next_close`
- 换手预算：`max_daily_turnover`，超出时**按比例部分调仓**（不是放弃调仓）
- 陈旧数据守卫：持仓标的失去数据 → 强制平仓，收取 taker 费 + 最宽价差

## 3.4 退市币

**这是本研究最大的数据缺陷，且不可修复。**

- OKX 公共 API 对已下架合约返回 `51001`（已实测：FTT、SRM、ANC、CVC、TON 全部不可得）
- 因此全部 161 个合约都是**幸存者**
- **偏差方向**：高估**多头腿**（下架的往往是曾经的动量领先者，之后归零）
- **压力测试**（30 次迭代，每次注入 10 个现实退市场景）：Sharpe 均值 **0.6902**
  （p05 0.5066，中位 0.7044，p95 0.9233，min 0.4685，max 0.9382），基准 **0.588**

  **如何解读这个结果（重要）**：注入退市后 Sharpe **上升**，说明策略并未把多头腿集中押在
  被注入的那些标的上。**但这不能修正生存偏差**——压力测试只是在现有（全幸存）池子里
  人为制造退市冲击，而真正的偏差来自**从数据里完全缺失的那些已退市合约**
  （2022 年后上市且在今日之前退市的，一个都不在池中）。测试能证明"策略扛得住退市事件"，
  **不能**证明"缺失的退市合约不会抬高历史收益"。因此该项仍标记为 **FAIL — 不可消除**。

## 3.5 新币

- 上市门槛由**首个有效 K 线**强制（`test_new_coin_is_never_held_before_it_lists`）

## 3.6 资金费数据质量（重要限制）

**只有 38 / 162 个合约有真正的币安历史回填。**

| 类别 | 数量 | 说明 |

# 4. Factor Analysis

## 4.1 相关性（冗余检测）

| 因子对 | 相关系数 | 结论 |
|---|---|---|
| momentum ↔ range_pos | **0.710** | **高度冗余** |
| flow ↔ hitrate | 0.197 | 最独立 |
| 其余 | < 0.4 | 可接受 |

## 4.2 因子消融（15 个子集，按 Sharpe 排序）

| 因子组合 | CAGR | Sharpe | 最大回撤 |
|---|---|---|---|
| **range_pos + hitrate** | 23.26% | **1.163** | −18.92% |
| **range_pos（单独）** | 21.97% | **1.111** | −19.84% |
| momentum + flow | 12.39% | 0.748 | −23.45% |
| flow + momentum + range_pos | 9.99% | 0.680 | −24.57% |
| flow + hitrate + momentum | 9.12% | 0.620 | −22.86% |
| **四因子全用（规格默认）** | **7.73%** | **0.588** | **−24.73%** |
| momentum + hitrate | 7.20% | 0.482 | −27.62% |
| momentum（单独） | 1.84% | 0.198 | −28.86% |
| flow + hitrate | −0.85% | −0.023 | −29.07% |
| **flow（单独）** | **−1.15%** | **−0.040** | −28.19% |
| **hitrate（单独）** | −3.84% | **−0.344** | −31.13% |

## 4.3 逐因子结论

**Momentum**：单独 Sharpe 0.198，7 天 IC +0.0230（t = 3.35）。
唯一有效的用法是**长周期**。4 小时 IC 显著为负（−0.0241, t = −3.41）。
与 range_pos 相关 0.710，**两者只应留一个**。

**Flow（策略核心卖点）**：**这一条必须分参数讨论 —— 见 §4.5。**
在**规格默认参数**（1d 调仓 + 50% 换手预算）下单独 Sharpe **−0.040**、CAGR −1.15%；
但在**推荐参数**（3d + 20% 预算）下单独 Sharpe **+0.542**、CAGR +5.54%。
也就是说「Flow 扣费后没有独立价值」这个结论**是默认实现参数的产物，不是因子的属性**。
两个参数下它都是**最弱的单因子**，但"最弱"与"为负"是截然不同的结论。
7 天 IC +0.0195（t = 2.83）在两个参数下都显著为正。

**Range Position**：**最强单因子**，单独 Sharpe 1.111，7 天 IC **+0.0448（t = 6.39）**，是全部因子里最显著的一项。但它与 momentum 高度相关，说明它承载了两者共有的大部分信息。

**Hit Rate**：单独 **最差**（Sharpe −0.344），但 7 天 IC **+0.0426（t = 6.38）** 却很高。
这个矛盾（IC 高但单独策略巨亏）说明 hitrate 的横截面排序在**长周期**上有信息，但其短周期噪声在扣费后完全主导。它与 range_pos 组合后 Sharpe 1.163（最佳）。

## 4.4 因子的一个反直觉发现

**增加因子会降低绩效。** 在默认参数下从 `range_pos + hitrate`（1.163）到四因子全用（0.588），
Sharpe 下降过半。原因：`momentum` 与 `range_pos` 冗余（相关 0.710，稀释有效信号），
而**换手与成本被推高**。

> 注意：这里的幅度（1.163 vs 0.588，+98%）是**默认参数下**的。换成推荐参数后
> 差距收窄到 1.549 vs 1.279（+21%）—— 方向不变，但**"加因子严重减分"的量化幅度被高估了**。
> 见 §4.5。

## 4.5 关键更正：因子结论依赖实现参数（消融 @ 3d 调仓 + 20% 换手预算）

同一套 15 个子集，只把调仓与换手预算换成推荐值，**结论的强度完全改变**：

| 因子组合 | Sharpe（默认 1d/50%） | Sharpe（推荐 3d/20%） | CAGR（推荐） | 最大回撤（推荐） |
|---|---|---|---|---|
| **range_pos + hitrate** | 1.163 | **1.549** | 17.27% | −11.36% |
| hitrate + momentum + range_pos | 0.680 | **1.374** | 15.14% | −10.38% |
| range_pos（单独） | 1.111 | 1.360 | 14.81% | −10.29% |
| momentum + range_pos | 0.748 | 1.300 | 14.14% | −11.56% |
| **四因子全用（规格默认）** | **0.588** | **1.279** | 14.36% | −9.49% |
| momentum + hitrate | 0.482 | 1.224 | 13.04% | −10.65% |
| hitrate（单独） | **−0.344** | **1.202** | 12.36% | −9.63% |
| momentum（单独） | 0.198 | 1.115 | 11.85% | −11.02% |
| **flow（单独）** | **−0.040** | **0.542** | 5.54% | −18.29% |

**三条更正**：

1. **`flow` 不是"无价值"，而是"最弱"**（−0.040 → +0.542）。默认参数下的负值由
   高频换手 + 高成本造成，与因子本身无关。
2. **`hitrate` 更戏剧**：−0.344 → +1.202。默认参数下它是"单独最差因子"，
   推荐参数下它是**第二好**。"IC 高但单独巨亏"的矛盾完全是成本造成的。
3. **全部子集的离散度大幅收窄**：默认下区间是 [−0.344, 1.163]（跨度为负到正），
   推荐下是 [0.542, 1.549]。**参数对了之后，因子选择退化为二阶问题**；
   参数错了之后，因子选择看起来像一阶问题。这是一个重要的方法论陷阱。

**因此推荐的因子集**：`range_pos + hitrate`（1.549）为首选；若要保守一些、
减少因子数带来的自由度，`hitrate + momentum + range_pos`（1.374）也可。
**两者都比规格默认的四因子好，且因子数更少 —— 符合"简单、稳定"的优先原则。**

> 方法学提示：这条更正是**在报告写完之后**通过补跑消融（`artifacts/tuned_abl/`）
> 才发现的。它说明**因子结论必须与实现参数一起报告**，否则会把参数问题误诊为因子问题。

## 7.2 成本情景阶梯

| 情景 | CAGR | Sharpe | 相对 gross 的差 |
|---|---|---|---|
| gross（无成本、无资金费） | 17.17% | 1.178 | — |
| no_trading_cost（免交易费，仍算资金费） | 17.86% | 1.218 | +0.68pp |

**自洽性验证**：`no_trading_cost > gross` 且 `net > no_funding`，两个缺口**同号**（都是资金费为正向收入）。
这是一条强校验：如果符号写错，这两个不等式会反向（见 §7.3）。

**交易成本吃掉约 10pp 年化收益。净 Sharpe 只有毛 Sharpe 的一半。**

## 7.3 已修正的缺陷 ①：资金费符号错误

**问题**：账本写的是 `net = gross − cost − fund`，而 `fund = −Σ w·rate` 本身已经是**带符号现金流**。
这是一次双重取负 → **把每一笔资金费成本都记成了收入**。`analysis/metrics.py` 的成本情景函数有同样的问题。

**证据链**（不依赖任何假设）：
1. `test_funding_sign_convention` 钉住了普适约定：正费率 ⇒ 多头付费。
2. 因此组合现金流必为 `−Σ w·rate`，引擎正是这么算的。
3. 用一个**恒定正费率**做决定性检验：`funding == −rate × net_exposure` 精确成立
   → 证明 `bars["funding"]` 列本身是**正确**的，错的只是它被折进 `net_ret` 的方式。

**修复**：`net = gross − cost + fund`；`no_trading_cost = gross + funding`。
新增 2 个回归测试（其中一个用恒定费率断言精确恒等式，与多空构成无关）。

**影响**（重估原持仓路径）：

| | 修复前 | 修复后 |
|---|---|---|
| CAGR | 6.85% | 8.13% |
| Sharpe | 0.533 | 0.618 |
| 最大回撤 | −24.66% | −24.20% |

经济含义：本组合实际是资金费的**净收取方**（≈+0.58%/年）。合理——市场中性组合把资金费净额对冲得
很好（`Σ|funding|` 是净额的 4.4 倍）。

## 7.4 已修正的缺陷 ②：强平成本未计入成本明细

**问题**：陈旧数据守卫把强平成本加到 `cost_total`（→ 进入 `net_ret`），
但**没有同步写入 `fee` / `spread` / `impact` 明细列**。
后果：`net_ret` 含这笔成本而拆解表不含 → **成本拆解系统性低估**。

**为什么原测试没抓到**：既有的账本恒等式测试跑在**无缺口**的面板上，强平路径从不触发，恒等式恒真。

**修复**：强平成本按 taker 费 + 最宽价差拆入对应明细列（并把名义额计入换手）。
新增回归测试 `test_ledger_identity_holds_when_a_position_is_force_closed`，
**注入必然触发强平的缺口**后断言 `net_ret == gross − (fee+spread+impact) + funding` 在每一根 bar 成立。
已验证：修复前该测试在 index 1500（强平那一根）失败，修复后通过。

**对当前结果的影响：零。** 真实运行的 `n_stale_marks = 0`（OKX 对已下架合约直接无数据，不存在"持仓卡在死币上"）。

| 随机打分 | 200 | 0.5881 | **−1.5179** | 0.4572 | −2.293 / −0.780 | **0.004975** | **1.00** |
| 分块打乱 | 30 | 0.5881 | **−0.8329** | 0.4580 | −1.424 / −0.262 | **0.032258** | **1.00** |

CAGR 维度同样显著：横截面置换与随机打分的 p 均为 0.004975（真实 CAGR 7.73% vs 安慰剂均值 −11.33% / −11.11%）。

**策略在三个零假设下全部跑赢 100% 的随机基准（百分位 = 1.00）。**

值得注意的是：**安慰剂的平均 Sharpe 是深度负值**（−0.83 到 −1.61）。
这不是噪声，而是**成本在起作用**——随机多空组合在高换手下必然被手续费与冲击成本磨死。
真实组合能到 +0.588，说明其横截面排序信息足以**克服这个成本基线**。

> 资金费符号修正对本节结论**无影响**：蒙特卡洛比较的是同一引擎下的真实打分与安慰剂打分，
> 符号修正同时作用于两者。实测三组 p 值与修正前**逐位一致**（0.005 / 0.005 / 0.032），
> 仅真实 Sharpe 从 0.5334 更新为修正后的 0.5881。

## 9.5 因子打乱（Factor Shuffle）

因子打乱已并入上表的置换检验框架：把逐因子 z-score 在横截面上独立打乱后重跑，
真实组合的 Sharpe 落在安慰剂分布的极右端（p ≤ 0.032），说明 alpha 来自**真实的横截面排序信息**，
而不是因子构造的偶然结构。

# 10. Capacity

| 资金规模 | CAGR | Sharpe | 年换手 | 滑点/冲击 | 成本拖累 | 最大参与率 |
|---|---|---|---|---|---|---|
| **$10K** | 10.92% | **0.724** | 115.8× | 0.038 | 8.73% | 0.0008% |
| $50K | 8.51% | 0.633 | 99.1× | 0.069 | 8.10% | 0.0034% |
| **$100K（=基准）** | **7.73%** | **0.588** | 97.2× | 0.095 | 8.40% | 0.0067% |
| $500K | 8.60% | 0.612 | 108.4× | 0.240 | 11.74% | 0.0356% |
| $1M | 5.51% | 0.462 | 92.4× | 0.272 | 11.20% | 0.0592% |
| $5M | 6.51% | 0.496 | 83.6× | 0.448 | 13.54% | 0.1767% |
| $10M | 5.53% | **0.399** | 84.9× | 0.528 | 14.69% | **0.2019%** |

- **Sharpe 在测试阶梯的最小规模（$10K）最高（0.724）**，随后随规模上升而**整体下降**，到 $10M 降至 0.399
  → **容量退化从第一档就开始了**，不存在一个"最优规模平台"
- **$100K 档与基准完全一致**（7.73% / 0.588）——这是一条自洽性校验，说明基准确实按 $100K 初始资金运行
- **$10M 时最大 ADV 参与率仅 0.20%** → 容量**不是**受流动性限制，而是受**冲击成本**限制
  （平方根冲击律下成本随资金规模上升：滑点从 0.038 升到 0.528，成本拖累从 8.73% 升到 14.69%）
- 阶梯**非单调**（$500K 的 Sharpe 0.612 高于 $100K 的 0.588，$5M 的 0.496 高于 $1M 的 0.462）
  → 成本与再平衡路径的交互不是平滑曲线，**不要把单点规模结论外推**
- `capital_at_50pct_of_peak = ∞` → 在测试阶梯内 Sharpe 从未跌到峰值的一半

**实践含义**：若按 $1M 以上规模运行，净 Sharpe 会掉到 0.40–0.46 区间，
再叠加 3d 调仓/20% 预算的改进（§7.5–7.6）才有实用价值。

# 11. Failure Analysis

**策略在什么时候失效**（每一项都有本研究的证据）：

### 11.1 高波动率（High Volatility）—— 最明确的失效条件

| 波动率状态 | Sharpe |
|---|---|
| LowVol | **0.894** |
| MidVol | 0.195 |
| **HighVol** | **0.158** |

高波动期 Sharpe 只有低波动期的 18%。HighVol 状态下平均毛敞口也被压到 0.293（风险层自动降仓）。

### 11.2 市场状态 / 趋势转换（Market Regime Shift）

| BTC 趋势强度 | Sharpe | 对总收益贡献 |
|---|---|---|
| **BTC_Strong** | **0.840** | +0.466 |
| BTC_Weak | 0.180 | +0.067 |
| **BTC_Flat** | **−0.051** | −0.021 |

| 趋势 | Sharpe |
|---|---|
| Bull | 0.568 |
| Sideways | 0.294 |
| **Bear** | **0.079** |

**这是本策略最大的结构性弱点**：它需要**强趋势**。BTC 横盘时 Sharpe 转负（−0.051）。
熊市也不赚钱（0.079）。收益的 46.6% 来自 BTC 强趋势时段（占样本 97%）。

### 11.3 动量反转（Momentum Reversal）

IC 在 4h 显著为负（−0.0227）、1h 为负（−0.0135）→ 短周期上**信号是反的**。
任何把持有期压到 1 天以内的实现都会在动量反转上被反复止损，同时支付最高成本
（1h 调仓净 Sharpe 0.065）。**这是"频率选择错误"导致的失效模式。**

### 11.4 山寨币崩盘 / Altcoin Season

| 山寨季节 | Sharpe |
|---|---|
| BTC_Dominance_Rising | 0.332 |
| Balanced | 0.387 |
| **AltcoinSeason** | **0.324** |

差异不大，但 **AltcoinSeason 的最大回撤最大（−25.19%）**。
山寨普涨/普跌时横截面离散度下降，多空两端相关性上升，对冲效果变差。

### 11.5 流动性危机（Liquidity Crisis）与资金费极端（Funding Extreme）

- 池在 2021-05、2021-07、2022-07 等月份急剧收缩（`pool_min` 低至 4–5 个名字）
- **池收缩到 4–5 个名字时，Top10 多 + Top10 空无法建满**，实际退化为低分散度的方向性暴露
- 这正是 2022 年 Sharpe −1.264 的重要背景
- **资金费极端**：x0–x2 阶梯 Sharpe 落在 0.588–0.703，**资金费极端不构成失效条件**（这是少数令人放心的结论）

### 11.6 换手预算设置错误（实现层失效）

如 §7.5，50% 预算是个陷阱。这不是市场原因，而是**参数选择错误**导致的失效。

### 11.7 失效条件的汇总判断

> **策略在"BTC 强趋势 + 低波动 + 长持有期（3d–7d）+ 低换手预算（10–20%）"下有效；
> 在"BTC 横盘 + 高波动 + 短持有期 + 高换手"下失效。**
> 这两组条件在本样本内都无法事先完美识别，因此策略存在显著的择时依赖。

# 12. Final Research Conclusion

### 12.1 是否存在统计证据？

**存在。** 三个随机零假设检验全部通过（p ≤ 0.032），Rank IC 在 7 天持有期显著为正（t = 4.69），
38 组参数全部正收益，三个参数网格全部为平缓区。
**但强度的量级是"弱到中等"**（ICIR < 0.15，净 Sharpe 0.588 在默认参数下）。

### 12.2 Alpha 来源是什么？

**不是策略名称所暗示的那个。**

| 来源 | 证据 |
|---|---|
| **区间位置（Range Position）** | 最强单因子，单独 Sharpe 1.111；7d IC +0.0448（t = 6.39） |
| **上涨持续性（Hit Rate）** | 7d IC +0.0426（t = 6.38）；与 range_pos 组合 Sharpe **1.549**（推荐参数下最佳）；单独 −0.344 → +1.202（参数极敏感） |
| 动量（Momentum） | 弱正向，7d IC +0.0230；与 range_pos 冗余（ρ = 0.710） |
| **流动性流向（Flow）** | **最弱单因子**：默认参数 −0.040、推荐参数 +0.542 → 参数敏感，**但并非无效** |
| 成本控制 | 主导性：毛 Sharpe 1.178 → 净 0.588；换手预算从 50%→20% 使 Sharpe 翻倍 |

**真实 alpha 是"长周期的横截面均值回复/位置效应"，而不是"流动性流向趋势"。**

### 12.3 哪些参数稳定？

- **调仓频率**：3d（1.244）与 7d（1.009）明显优于 1d（0.588）与 1h（0.065）；IC 衰减支持长持有期 → **稳定**
- **换手预算**：10–20% 优于 ≥50% → **稳定且重要**
- **Beta 方法**：B 法真中性（|β| 0.0086）优于 A 法 → **明确**
- **K 值**：K=5/10/15 差异不大（0.525/0.588/0.503）→ **稳定**
- **成交价模型**：4 种模型 Sharpe 落在 0.574–0.660 → **稳定**
- **参数网格整体**：3/3 判定 plateau，38/38 正收益 → **稳定区确实存在**
- **池子定义（流动性门槛是关键约束）**：`$3M` 门槛（可交易池 10–22 个名字）优于放宽到 `$1M` 的宽池
  —— 宽池在其最佳频率 7d 也只有 Sharpe 1.007、回撤 −14.5%，仍低于窄池 3d+20% 预算的 1.279 / −9.49%
  → **宁可窄而深，不要宽而浅**（注：宽池在 3d/7d 下的日换手已低于 20%，故"宽池 + 低换手"这一组合
  已由频率阶梯完整覆盖，无需额外运行）

### 12.4 哪些参数敏感？

- **`min_abs_score`**：0.5 时 Sharpe 1.116，1.0 时 0.892，0.75 时仅 0.493 → **敏感、非单调**
- **`max_daily_turnover`**：0.2 与 0.5 之间 Sharpe 差 1.03 → **极度敏感**（但方向明确：低更好）
- **`momentum_lookback`**：252 bars 时 0.304（最差），720 bars 时 0.986 → **敏感**
- **`flow_short` / `flow_long`**：网格内 0.340–0.951 → **敏感**
- **资金费倍数**：0.588–0.703，非单调 → 敏感但幅度可控

### 12.5 最大风险是什么？

按严重程度排序：

1. **生存/退市偏差不可消除** → 多头腿收益被系统性高估，且无法量化修正
2. **业绩集中在 2021 与 2026，2022–2025 平坦** → 样本外"稳定重复"证据不足
3. **单一币（SOL）贡献 41% 净 PnL** → 结果对 1 个标的的实现高度依赖
4. **BTC 横盘时策略失效（Sharpe −0.051）** → 存在无法事先识别的择时依赖
5. **可交易池仅 10–22 个名字** → 分散度低、容量有限、且在流动性危机中急剧收缩
6. **策略命名来源的 Flow 是最弱因子（推荐参数下 0.542），主力因子（range_pos / hitrate）与叙事无关** → 经济逻辑的可解释性弱
7. **资金费 61.5% 的换手使用代理值** → 该项为二阶（+0.58%/年）但仍是数据瑕疵

### 12.6 样本外是否成立？

**部分成立。**
- 走向前 4 折 test Sharpe：0.330 / 0.044 / 0.217 / 1.557 —— **全部为正，但 3 折有明显衰减**
- `tuned` 配置（3d + 20% 预算）4 折 test Sharpe：1.202 / 0.929 / 2.649 / 1.410 —— **全部 ≥ 0.93，且逐年全部为正**
- 结论：**"存在 alpha"这一命题在样本外站稳了；"在默认参数下可直接实盘"没有站稳。**

### 12.7 实盘前还缺什么验证？

按优先级：

1. **补全退市合约数据**（OKX 无此数据，需第三方数据源或交易所归档）—— 不可回避，否则多头腿收益不可信
2. **重建资金费历史**：加快币安限流重试，把 124 个中位代理升级为真实拼接（预期影响 ±0.1–0.2%/年）
3. **标的范围收敛**：剔除代币化股票/商品（占成本 4.10%），使策略定义与执行假设一致
4. **降低频率依赖**：确认 3d/7d 调仓在**真实成交**下仍成立（研究用 next_open，实盘会有排队与部分成交）
5. **纸面交易（Paper Trading）**：至少 3 个月，验证
   (a) 信号到成交的实际滑点是否需要上调
   (b) 3d 调仓下的真实换手与佣金归属（maker/taker 混合比例）
   (c) 资金费的实际收取方向与本研究一致
6. **实盘架构**（本阶段仅给接口，未实现）：
   - 数据层：增量拉取 + PIT 快照落盘（每日 UTC 00:00 冻结）
   - 信号层：复用 `factors/` + `signals/`，输入冻结快照，输出目标权重
   - 风控层：复用 `risk/`，硬编码回撤阶梯与强平距离检查
   - 执行层：TWAP/冰山单拆单，ADV 参与率上限 5%，实际成交价回写
   - 对账层：每日比对预期持仓 vs 实际持仓，资金费与手续费逐笔归集

### 12.8 一句话结论

> 在真实加密货币永续市场中，这个横截面市场中性策略**确实存在统计上可验证的 alpha**
> （通过全部随机基准检验），**但其经济意义在规格默认参数下不足**
> （净 Sharpe 0.588、CAGR 7.73%、回撤持续 4.5 年），
> 且 **alpha 的真实来源（区间位置 + 上涨持续性）与策略命名（流动性流向）不符**，
> **Flow 是最弱的因子 —— 但不是无效因子**（推荐参数下 +0.542；默认参数下的负值是成本造成的）。
> 把调仓改为 3d、换手预算降到 20% 后 **Sharpe 升到 1.279、CAGR 14.36%、回撤降到 −9.49%**
> **（回撤持续期从 1,652 天缩短到 270 天）且逐年为正**，
> **说明限制绩效的是实现参数而非 alpha 本身**。
> 在补全退市数据、重建资金费、收敛标的范围并完成纸面交易验证之前，
> **不具备投入真实资金的条件。**

本节记录**在报告主体写完之后**通过补充实验发现的、与主体结论有出入的两项事实。

## 13.1 因子结论依赖实现参数（重要更正）

主体 §4.2–§4.4 的因子消融是在**规格默认参数**（1d 调仓 + 50% 换手预算）下做的。
在推荐参数（3d + 20% 预算）下重跑同 15 个子集后，**结论强度大幅改变**：

| 因子（单独） | 默认参数 Sharpe | 推荐参数 Sharpe |
|---|---|---|
| `hitrate` | **−0.344** | **+1.202** |
| `flow` | **−0.040** | **+0.542** |
| `momentum` | 0.198 | 1.115 |
| `range_pos` | 1.111 | 1.360 |
| 四因子全用 | 0.588 | 1.279 |
| `range_pos + hitrate` | 1.163 | **1.549** |

**两个"无效因子"的负值完全由高频换手与成本造成，不是因子的属性。**
因此：
- §4.3 中「Flow 无独立价值」的表述已更正为「Flow 是最弱因子，但非无效」；
- §1.4 与 §12 中引用「flow 单独 −0.040 / hitrate 单独 −0.344」作为"因子无效"证据的地方
  已补上参数条件；
- 「加因子严重减分」的幅度从 +98%（1.163 vs 0.588）更正为 **+21%（1.549 vs 1.279）**。

**方法学教训**：因子层面的结论**必须与实现参数一起报告**，否则会把参数问题误诊为因子问题。

## 13.2 权重 sizing 静默退化（实现偏差）

`portfolio/construct.py:118`：当 `max_weight_per_instrument × n ≤ 1` 时，
函数**退化为等权**并丢弃规格要求的 `w_i ∝ |score_i| × 1/vol_i`。

规格默认 `top_k = 10` 与 `cap = 0.10` 使 `cap × n = 1.0`，**恰好命中该分支**。
实测：`K=10, cap=0.10` 时每侧权重恒为 `0.1`（不同取值个数 = 1）；
且 `cap=0.10` 与显式 `vol_weight_power=0, score_weight_power=0` 的结果**逐字节相同**。

**⟹ 本报告全部 headline 结果实际为「等权」，而非「逆波动率加权」。**
这是一个**规格与实现之间的偏差**，不是调参问题。

启用真正 sizing（`cap = 0.20`）后：Sharpe 1.279 → **1.378**、CAGR 14.36% → **16.65%**、
MDD −9.49% → −12.25%。详见 `artifacts/OPTIMIZATION.md` §2.2。
