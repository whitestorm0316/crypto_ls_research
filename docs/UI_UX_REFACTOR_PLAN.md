# 前端 UI/UX 重构方案

> 审查对象：`webapp/` 控制台（2026-11-09）
> 原则：**先诊断、后改造**；API 契约不变；不删已有功能；分阶段实施。

---

## 一、现状盘点（代码事实，非印象）

### 1.1 规模

| 文件 | 行数 | 体积 | 说明 |
|---|---|---|---|
| `static/app.js` | 4300 | 219 KB | **140 个顶层函数**，无模块边界 |
| `static/style.css` | 618 | 32 KB | 69 个类，12 种字号，9 种间距 |
| `static/index.html` | 37 | 1.8 KB | 只有壳：顶栏 + 空侧栏 + 空主区 |
| `server.py` | 1538 | — | 12 个 API 端点 |
| `live_api.py` | 987 | — | 28 个 API 端点 |
| `spec.py` | 622 | — | 参数规格唯一来源 |

### 1.2 架构

- **单页 + 3 个 tab**：`回测结果` / `交易记录` / `交易台`，hash 路由 `#result|#trades|#live`。
- **渲染方式**：字符串拼 HTML → `innerHTML`；`preserveUi()` 负责快照/回填输入框（焦点、未提交内容）。
- **全局状态** `S`：约 50 个顶层键，其中 `S.live` 嵌套约 30 个键，全部可变。
- **轮询**：`/api/runs` 每 2.5s、`/api/live/auto` 每 10s（仅交易台）。
- **布局**：`.main { grid-template-columns: 412px 1fr }`，**侧栏常驻**。

### 1.3 七个目标模块 vs 现状

| 目标模块 | 现状 | 实际位置 |
|---|---|---|
| Dashboard | ❌ **不存在** | KPI 散在回测结果顶部；账户散在交易台 |
| Strategy Lab | ⚠️ 半个 | 左侧栏「预设 / 运行范围 / 参数分组」，无版本管理 |
| Backtesting | ✅ 主体已有 | tab1：KPI、曲线、年度表、运行记录、日志、等价命令行 |
| Trading Terminal | ⚠️ 半个 | tab3：账户/信号/净值/计划/闸门/订单表；**无行情、无 K 线、无挂单、无撤单** |
| Automation | ⚠️ 折叠 | tab3 里一个 `<details>` |
| Risk Management | ⚠️ 折叠 | tab3：风控闸门 + 限额子标签 + 杠杆面板 |
| Data Center | ❌ **不存在** | 只有「缺数据」时的一条红 banner + 宇宙体检横幅 |

### 1.4 交易台的真实结构（一个 tab 装 10 段）

```
① 吸顶操作条（模式 + 连接状态 + 主按钮 + 熔断）
② 宇宙漂移横幅
③ 两列：账户与连接 | 信号
④ 账户净值历史（曲线/K线 + 7/30/90/全部）
⑤ 下单计划（含清仓按钮）
⑥ 风控闸门
⑦ <details> 模式与交易场所
⑧ <details> 自动任务
⑨ <details> 执行日志
⑩ 子标签：订单 | 成交 | 运行记录 | 风控限额
```

**交易终端 + 自动化 + 风控 + 数据**四件事挤在一个滚动流里，靠 3 个折叠区缓解。

## 二、逐页审查

### 2.1 全局壳

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| G1 | 侧栏 412px **常驻所有页面** | `renderSide()` 只在 boot 调用一次；`.main` 固定 `412px 1fr` | 交易台/交易记录页上，一块**回测参数面板**永久占用 32% 宽度，且内容与当前任务无关 |
| G2 | 登录页在 `#content` 内渲染 | `authLogin()` → `$('#content').innerHTML` | 未登录时**顶栏（含「运行回测」按钮）与空侧栏仍然可见**，且 420px 表单被挤在右侧 |
| G3 | 顶栏 pill 语义不明 | 「统一一致」「漂移」「阻断」「运行中」 | 用户需读 title 才知道是什么；4 个 pill 抢走品牌与主操作之间的注意力 |
| G4 | 无一级导航 | 只有 3 个 tab，位于内容区顶部 | 7 个模块无处安放；tab 与页面标题视觉权重接近，层级不清 |
| G5 | 主题默认跟随 OS | `:root` 是浅色；`data-theme=""` | 「专业终端」定位要求**默认暗色**，浅色作为可选 |

### 2.2 回测结果页

| # | 问题 | 证据 |
|---|---|---|
| R1 | **3 条全宽 banner 叠在数据之前** | 宇宙体检干净 + 宇宙有漂移 + 风控阻断，吃掉约 250px 垂直空间 |
| R2 | 净值曲线面板曾出现大面积空白 | `.ui_preview/ui_dark.png` 截图里画布未绘制。`drawChart()` 有 `clientWidth===0` 早退保护，但**只有 `window.resize` 监听、无 `ResizeObserver`** ⇒ 布局在无窗口尺寸变化的情况下定型（tab 切换、异步内容撑开）时不会重绘 |
| R3 | KPI 只有 4 张，信息密度偏低 | Sharpe / CAGR / 最大回撤 / 换手，右侧大片留白 |
| R4 | 运行记录行信息过密但可扫性差 | 一行塞：复选框 + 标签 + tag + 时间 + 耗时 + Sharpe + CAGR + 状态 + 删除 |
| R5 | **无法取消正在跑的回测** | 后端 `POST /api/runs/<id>/cancel` 存在（`server.py:946`），**前端 0 处调用** |
| R6 | 多回测对比只有「叠加曲线」 | 无横向指标表；`paintCmpTable()` 只有极简实现 |

### 2.3 交易记录页

| # | 问题 | 证据 |
|---|---|---|
| T1 | 三张表（归因 / 流水 / 成交）各自分页 | `pagerHtml()` 三处独立 |
| T2 | 筛选栏与标签选择器分散 | `tagPicker()` + 三个独立筛选状态 |
| T3 | 空态是纯文本 | 33 处 `class="empty"` 全部是「暂无记录」「正在读取…」 |

### 2.4 交易台

| # | 问题 | 证据 |
|---|---|---|
| L1 | **挂单不可见、不可撤** | `okx_private.cancel_order / cancel_all / orders_pending` 三个方法**都已实现**，engine / live_api / 前端**全未暴露** |
| L2 | 订单表裸枚举 | `state` 直接显示 `filled` / `live`；`action` 显示 `flip_close` / `increase`（同类问题项目已为自动任务修过 `LIVE_ACTION_LABEL`，订单表漏了） |
| L3 | 危险操作分散三处 | 熔断在吸顶条、清仓在计划面板底部、停止守护进程在**折叠区**里 |

| L5 | 无行情、无 K 线 | 净值曲线是**账户净值**，不是标的行情；无盘口 |
| L6 | 危险操作用原生对话框 | `confirm()` ×3、`alert()` ×5 |
| L7 | 空/加载态无骨架 | 0 处骨架屏；`liveSkeleton()` 是静态占位 |

| # | 问题 | 量化证据 |

| D5 | 语义 token 缺层 | 只有 `--bg/--panel/--panel-2` 三层，缺 elev / text-3 / border-strong / chart 系列 |

### 2.6 架构风险（改造前必须先处理）

| # | 风险 | 证据 | 应对 |
|---|---|---|---|
| A1 | `app.js` 被 **8 个 harness + 2 个守卫测试**直接读取 | `scripts/{smoke_ui,smoke_live,check_dom_refs,check_js,verify_*}.js`、`test_console_api_contract.py`、`test_universe_drift.py` | **P0 阶段不拆**；拆分放最后，先改 harness |

| A3 | 守卫测试按函数名抓取 | `test_console_api_contract.py` 正则找 `deleteRun()` 与 `fetch('/api/runs/'...)` | 改名/搬移会静默失效 → 每次搬移同步更新断言 |

## 三、目标信息架构

### 3.1 全局壳

```
┌──────────────────────────────────────────────────────────────────────┐
│ ▣ 品牌    [纸面|模拟|实盘]   ⌕ 搜索        ⧉ 任务(3)  ◔ 通知(2)  ⚙ 账户 │ 56px
├────┬─────────────────────────────────────────────────────────────────┤
│ ◎  │                                                                 │
│ 📊 │                                                                 │
│ 🧪 │                       页面内容区                                  │
│ ▶  │                                                                 │
│ ⇄  │                                                                 │
│ ⚙  │                                                                 │
│ 🗄 │                                                                 │
│    │                                                                 │
│64px│                                                                 │
└────┴─────────────────────────────────────────────────────────────────┘
```

- 左侧 **64px 图标导航**（hover 展开为 200px 带文字），7 个模块。
- **参数面板不再是常驻侧栏**，改为 Strategy Lab / Backtesting 页内的**右侧抽屉**（宽 400px，可收）。
- 顶栏只保留：品牌、环境切换、搜索、任务中心、通知中心、账户。
- 环境切换（纸面/模拟/实盘）做成**分段控件**，实盘态整条顶栏加红色左边框，避免误操作。

### 3.2 路由

| 路由 | 模块 | 内容 |
|---|---|---|
| `#/dashboard` | Dashboard | 账户净值、今日 P&L、回撤、敞口、风控状态、系统健康、最近事件 |
| `#/lab` | Strategy Lab | 策略列表、因子、参数、版本快照 |
| `#/backtest` | Backtesting | 任务队列 + 结果 + 横向对比 |
| `#/trade` | Trading Terminal | 行情、持仓、挂单、计划、成交 |
| `#/auto` | Automation | 自动实例、调度、执行日志 |
| `#/risk` | Risk | 限额、杠杆、敞口、五件事 |
| `#/data` | Data Center | 数据源、覆盖度、质量、任务、宇宙 |

**兼容**：旧 hash 保留并重定向（`#trades` → `#/backtest?tab=trades`，`#live` → `#/trade`），`?tag=` `?view=` 深链继续可用。

### 3.3 各页布局要点

**Dashboard**（首屏决策页）
```
┌ 净值卡（大数 + 今日 P&L + 30 日 sparkline）┬ 回撤卡 ┬ 敞口卡 ┬ 保证金占用 ┐
├──────────────── 净值曲线（主视觉）──────────────────────────────────────┤
├ 风控状态（闸门 5 项）─┬─ 系统健康（数据新鲜度/宇宙漂移/守护进程/任务）──┤
├──────────────── 最近事件（时间线，10 条）───────────────────────────────┤
```

**Backtesting**
```
左：任务列表（状态点 + tag + 指标 + 取消/删除）
右：结果（KPI 行 → 曲线 → 年度表 → 归因）
上：配置抽屉（预设 / 运行范围 / 基础参数 / 高级参数折叠）
下：横向对比表（勾选 2+ 任务 → 指标并排 + Δ 列）
```

**Trading Terminal**
```
左栏 60%：行情/K线（标的切换）→ 持仓表 → 挂单表（含撤单）
右栏 40%：下单计划 → 风控闸门 → 执行
吸顶：环境 + 连接 + 熔断 + 危险操作菜单
```

**Risk**
```
限额表单（基础/高级）| 杠杆面板 | 敞口分解 | 危险操作五件事（分级）
```

## 四、设计系统规范

### 4.1 Tokens（`style.css` `:root`）

```css
/* 字号 7 档 */
--fs-caption: 11px;  --fs-sm: 12px;   --fs-body: 13px;
--fs-title: 15px;    --fs-section: 17px;
--fs-display: 20px;  --fs-kpi: 28px;

/* 间距 8 档（4pt 网格） */
--sp-1: 2px;  --sp-2: 4px;  --sp-3: 6px;  --sp-4: 8px;
--sp-5: 12px; --sp-6: 16px; --sp-7: 24px; --sp-8: 32px;

/* 圆角 3 档 */
--r-sm: 6px; --r-md: 8px; --r-lg: 12px;

/* 新增语义层 */
--bg-elev-1: var(--panel);
--bg-elev-2: var(--panel-2);
--text-3: color-mix(in srgb, var(--muted) 80%, transparent);
--border-strong: color-mix(in srgb, var(--border) 70%, var(--text));
--chart-1..5: …;
```

**暗色为默认**：`:root` 直接放暗色值；`:root[data-theme="light"]` 覆盖为浅色。

**保留不变量**（不得改动）：
- 涨红跌绿（`--up` 红、`--down` 绿，中国惯例）
- `fmt.dol` 两位小数、负号在 `$` 前
- 所有指标来自 `/api/spec`，前端不写死

### 4.2 组件清单（新建 `static/ui.js`，平铺）

| 组件 | 替代什么 | 关键约束 |
|---|---|---|
| `ui.card()` | 手写 `.panel` | head/actions/body/footer 四段固定 |
| `ui.stat()` | `kpiCard()` | label / value / delta / sparkline，tabular-nums |
| `ui.table()` | 5 处手写表 | sticky thead、数字右对齐、行 hover、空态、密度切换 |
| `ui.badge()` | `.pill` / `.tag` / `.chip` 混用 | 语义 ok/warn/danger/neutral/info |
| `ui.modal()` | `confirm()` ×3 | 支持 danger 变体 + 输入确认短语 |
| `ui.toast()` | `alert()` ×5 | 右下角堆叠，4s 自动消失，错误常驻 |
| `ui.skeleton()` | `class="empty"` 的「正在读取…」 | 表格骨架 / 卡片骨架两型 |
| `ui.empty()` | 33 处纯文本空态 | 图标 + 标题 + 说明 + 主操作 |
| `ui.drawer()` | 常驻 412px 侧栏 | 右侧滑出，400px，Esc 关闭 |
| `ui.tabs()` / `ui.seg()` | `.tab` / `.segbtn` | 键盘左右切换 |
| `ui.tooltip()` | `title=` 属性 | 支持富文本，延迟 400ms |

### 4.3 枚举翻译表（消除裸代码泄漏）

| 域 | 裸值 | 显示 |

## 五、关键交互流程重设计

### 5.1 回测任务：创建 → 执行 → **取消** → 查看

```
[配置抽屉] 预设 → 运行范围 → 基础参数(可见) → 高级参数(折叠)
    ↓ 点「运行回测」
[任务卡] 排队中 → 运行中(进度条+耗时) → 完成
                                    ↘ [取消]  ← 现在缺失
    ↓ 点击任务卡
[结果区] KPI → 曲线 → 年度表 → 归因 → 日志 → 等价命令行
```

**改动**：接上已有的 `POST /api/runs/<id>/cancel`（后端无需改动）。
**确认**：取消正在运行的任务需 `ui.modal` 二次确认（会丢弃部分产物）。

### 5.2 危险操作五件事（分级，统一入口）

| 级别 | 操作 | 语义 | 后端 | 确认强度 |
|---|---|---|---|---|
| L1 | **暂停策略** | 不再开新仓，持有到下一周期 | ❌ 需新增 | 单击 + toast |
| L2 | **停止策略** | 停调度线程，不再自动执行 | ✅ `/api/live/auto/stop` | 单击 + 状态回显 |
| L3 | **撤单** | 撤销所有未成交挂单 | ⚠️ 底层已有，需暴露 | 输入确认短语 |
| L4 | **平仓** | 市价清掉全部持仓 | ✅ `/api/live/flatten` | 输入确认短语 |
| L5 | **紧急停止** | 熔断 + 撤单 + 平仓 | ⚠️ 需编排 | 短语 + 二次点击 + 10s 倒计时 |

**UI**：顶栏右侧一个 `⋯ 危险操作` 菜单，展开列出 5 项，每项带一行说明「做什么 / 不做什么」。
绝不再把「熔断」「清仓」「停止」分散在三处。

### 5.3 多回测横向对比

```
勾选 2+ 任务 → [对比] 按钮亮起 → 对比视图
┌──────────┬────────┬────────┬────────┬──────┐
│ 指标      │ run A  │ run B  │ run C  │ Δ vs 基线 │
├──────────┼────────┼────────┼────────┼──────┤
│ Sharpe   │ 1.94   │ 1.72   │ 2.01   │ +0.07 │
│ CAGR     │ 31.2%  │ 24.1%  │ 33.0%  │ +1.8pp│
│ 最大回撤  │ -12.8% │ -18.4% │ -11.2% │ +1.6pp│
│ 换手     │ 29.5   │ 41.2   │ 27.1   │ -2.4  │
└──────────┴────────┴────────┴────────┴──────┘
+ 参数差异表（只列不同的项）
```

数据来源：`/api/runs/<id>` 已有 `result` / `delta` / `argv` / `overrides`，**无需新端点**。

### 5.4 任务中心 + 通知中心

**任务中心**（顶栏 `⧉`）：聚合两个独立队列
- 研究队列 `JOBQ`（`/api/runs` 的 `active` + `queued`）
- 实盘作业队列（`/api/live/jobs`）
- 统一卡片：类型 / 标题 / 状态 / 进度 / 耗时 / 取消

**通知中心**（顶栏 `◔`）：聚合三类事件
- 回测完成/失败（`/api/runs` 状态迁移）
- 实盘执行（`runs.jsonl` 的 `action` / `warnings` / `notify`）
- 系统告警（数据陈旧、宇宙漂移、守护进程离线）

> 需要**新增一个只读聚合端点** `/api/events`（追加，不改现有契约）。

### 5.5 三态规范

| 状态 | 规范 | 现状 |
|---|---|---|
| 空 | 图标 + 标题 + 一句说明 + 主操作按钮 | 纯文本「暂无记录」×33 |
| 加载 | 骨架屏（表格 5 行灰条 / 卡片 3 块） | 纯文本「正在读取…」 |
| 错误 | 错误码 + 人话原因 + 下一步动作 + 重试按钮 | 分散的 banner，无重试 |

## 六、分阶段实施计划

> 每阶段独立可交付、可回滚。P0 全是前端改动，后端零改动。

### P0 — 设计系统与壳（不改业务逻辑）

| 步骤 | 内容 | 涉及文件 | 风险 |

## 七、兼容性与不变量

### 7.1 必须保持不变

1. **40 个现有 API 端点**全部保留，路径、参数、响应形状逐位不变；新增只追加。
2. **唯一来源原则**：指标来自 `/api/spec`；`ACCEPTED_FACTORS` / `ACCEPTED_REBALANCE_DAYS` 派生到 `engine.DEFAULT_SIGNAL` 与 `spec.OPTIMAL_OVERRIDES`，前端不得写死。
3. **涨红跌绿**（中国惯例）、`fmt.dol` 两位小数。
4. **实盘确认短语**机制（服务端下发，前端校验）。
5. **`preserveUi()`** 输入框保护（否则「一输入就清空」回归）。
6. **`/api/` 错误必须是 JSON**（否则前端根因全被藏住）。

### 7.2 守卫测试策略

- P0/P1 阶段：**不改任何现有断言**，只加新断言。
- P2-5 拆分阶段：先改 harness（8 个 JS 脚本 + 2 个守卫测试）**并验证它们仍能抓到变异**，再搬代码。
- 新增交互必须有**拒绝路径**测试（例如：取消已完成任务应返回提示而不是崩溃）。

### 7.3 回滚

每个阶段一个 commit，`style.css` 与 `app.js` 的改动都保持**向后兼容**（旧类名保留一个版本），可单点 revert。

## 八、建议的启动顺序

1. **P0-1 + P0-2**（tokens + 组件）——纯增量，视觉立刻统一，风险最低。
2. **P0-3**（壳 + 登录页）——信息架构成型，后续页面才有地方放。
3. **P0-5**（回测取消）——功能缺口里最便宜、收益最直接的一个。
4. **P1-1**（Dashboard）——第一个真正的「决策页」。
5. 其余按 P1 → P2 推进。

> 不建议先做 Trading Terminal 的行情/K 线：它需要新数据端点 + 新图表库，投入大且不影响当前决策效率。
