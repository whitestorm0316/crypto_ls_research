### Q54：加登录 + 二重认证 + 外网访问（TOTP / 会话 / TLS）

用户要求：「添加创建账号+登陆机制+二重认证」。确认三个选择：
**外网访问** + **TOTP 验证器 App** + **单用户**。

#### ① 起点：控制台原本**完全没有鉴权**
它绑 `127.0.0.1`，而"只有本机能访问"被当成了安全边界 —— 但那是**本机进程之间
没有边界**。同一台机器上任何进程（浏览器里任意网页、随手跑的脚本、装错包的 CLI）
都能 `POST /api/live/execute` 下真钱单、`GET /api/live/creds` 读 key、
`POST /api/live/flatten` 一键平仓。
⇒ 加鉴权解决的**首先**是本机越权，外网访问只是把同一道墙延伸到更远。

#### ② 实现（`webapp/auth.py`，**纯标准库、无第三方依赖**）
- **口令**：`hashlib.scrypt`(n=2^14)，每账号独立 salt，串 `scrypt$n$r$p$salt$hash`
  **自描述**（调参不迁移）。比较用 `hmac.compare_digest`。
- **TOTP**：手写 RFC 6238（30s/6 位/SHA1），**对过 6 组官方向量**。
  ±1 步容忍漂移；**拒重放**（记已用步数，只留最近 20 个）。
- **会话**：`secrets.token_urlsafe(32)`，**只存 sha256**；固定 8 小时、**不滑动续期**。
- **两步登录票据**：口令过了只发 120 秒**一次性**票据（`LoginFlow.claim` 用 `pop`）。
  ⚠️ 没有它，二重认证会被**降级成单因子**（拿口令直接调第二步）。
- **节流**：连续 5 次失败锁 5 分钟。

#### ③ 闸门：**唯一入口 + 白名单**
`server.py` 的 `do_GET/do_POST/do_DELETE` 开头各一行 `if not self._gate()`。
**不散在每个端点里** —— 散着做一定会漏一个，而漏的那个可能是 `execute`。
`_PUBLIC_API` 是**白名单**（新增端点默认"要登录"）。
未登录回 **JSON 401 + `need_login`**（不是 302：前端一律 `resp.json()`，
HTML 重定向页会抛 `Unexpected token '<'`、真因全被藏住）。
⚠️ 闸门在**路由之前** ⇒ 未登录时"存在"与"不存在"的路径回**同一个** 401，
否则是一条**枚举端点**的通道（已加守卫）。

#### ④ 外网访问：**明文绑非本机 ⇒ 拒绝启动**
`_resolve_bind()`：默认 `127.0.0.1` 明文可以；给 `LS_HOST` 但没证书就
**sys.exit**（口令与 TOTP 码明文过网 + 登进来能下真钱单 ⇒ 警告框拦不住任何人）。
TLS 从 `LS_TLS_CERT/LS_TLS_KEY` 加载，`minimum_version=TLSv1_2`。
⚠️ Cookie 的 `Secure` **只在 TLS 下加** —— 明文加它浏览器会丢 Cookie，
本机开发就永远登不上（一个"安全设置把功能全废"的典型）。实测两种都验过。
另加 `scripts/START_CONSOLE_TLS.sh`。

#### ⑤ 🔴 我自己踩的坑（都被测试/实测抓）
- **`AUTH_FILE` 落到仓库外面**：`ROOT` 从 `crypto_ls_research/execution/credentials.py`
  **抄**的，那文件在根下**两层**（`dirname(dirname())` + `..`），而 `webapp/auth.py`
  只在**一层** ⇒ 多爬一级 ⇒ 凭据写到 `~/code/config/auth.json`。
  后果：**`.gitignore` 管不到它**（凭据在仓库外裸奔）、删仓库里的文件删不掉账号、
  换 clone 后"登录不上"而毫无线索。已修 + 加两条守卫（含 `git check-ignore` 实查）。
- **变异测试里 2 条漏网，都是我的测试弱**：
  - `==` vs `compare_digest` **行为完全相同** ⇒ 任何只验 True/False 的测试都抓不到。
    必须**断言语义**（源码里有 `compare_digest`）。
  - "读不到配置当已配置"漏网：`_read()` 有**两条**"读不到"的路径（`except` 的
    OSError/ValueError、`else {}` 的类型不对），我只测了前者 ⇒ 补"内容是 list/str"
    的用例。
  - 又一条：只断言"函数里有 `compare_digest`"不够（文件里有两处）⇒ 精确到
    `compare_digest(totp_at(`。
- **契约测试 3 条变红**（404/501 → 401）：这是**正确的新行为**，但 fixture 得先登录。
  改成**真走一遍注册+两步登录**（而不是伪造 session token）——否则"登录链路坏了"
  在这份测试里永远看不出来。
- **冒烟 stub 断言 `boot();` 结尾** ⇒ 入口换成 `authRender()` 后直接报错（消息自己
  说了"stub 需要更新"）。冒烟也已接入真实登录。

#### ⑥ 验证
- 全量 **698+ passed**；`test_auth.py` **36 条 / 变异 10/10**。
- 手工实测：未登录 401（含不存在路径同样 401）、错口令 401、错 TOTP 401、
  **重放同一 TOTP 401**、登出后 cookie 失效、带 cookie 200；
  TLS 下 Set-Cookie 含 `Secure`、明文下**不含**；明文绑 `0.0.0.0` 拒绝启动。
- 已删除我建的测试账号，交由用户自己首次设置（`config/auth.json` 已就位）。

### Q55：登录页打开是空白 / 只有个壳 —— **白名单路径写错**

用户截图问「啥玩意 怎么只有这个界面」。

#### 根因
`_PUBLIC_STATIC` 我**手写**成 `("/", "/index.html", "/app.js", "/favicon.ico",
"/style.css")`，而 `index.html` 里实际写的是 **`/static/app.js`** 与
**`/static/style.css`** ⇒ 这两个被鉴权闸门 **401 挡掉** ⇒ 页面 HTML 加载了
但 CSS/JS 全没 ⇒ 浏览器里只剩一具没有样式的空壳。
⚠️ **控制台日志一切正常**（静态资源被挡不打日志），所以从服务端看不出问题。

#### 修法
- 白名单改成**前缀** `_PUBLIC_STATIC_PREFIX = ("/static/",)`，
  `_PUBLIC_STATIC` 只留 `("/", "/index.html", "/favicon.ico")`。
  **前缀匹配**而不是逐条列举文件名 —— 列举就会和页面实际路径漂移。
- 删掉旧定义时我**顺手把 `_PUBLIC_API` 也删了**（一次编辑覆盖两处），
  靠 `grep` 复查才发现 —— **改定义块之后要复查整块还在不在**。

#### 守卫（这是关键）
`test_every_asset_index_html_references_is_public`：
**从 `index.html` 里正则抓 `src=`/`href=`**，逐个断言放行。
⚠️ **不要在测试里再抄一份路径清单** —— 那份也会漂移，而漂移就是这次的成因。
另两条：`/static/` 必须走前缀、且前缀不能顺手放行 `/api/`。
实测把 bug 注入回去 ⇒ 测试点名 `['/static/style.css', '/static/app.js']`。

#### 🧭 教训（值得记）
**"我列了一份清单"和"页面实际请求什么"是两个东西。** 凡是白名单/映射表，
能从前端**抓**就别手写；手写的那份永远会在某个时刻和另一头不一致，
而这次的代价是"整个页面打不开"。

### Q56：看不到「创建账号」按钮 —— `_gate` 里**把白名单抄了第二遍**

我说"磁盘上 account 已删"，但**其实没删干净**：我 10:20 建的测试账号 `chen`

⇒ 教训：**说"已删掉"之后要复查**，尤其是我自己后续又动了那个目录。

#### 第二个错（真正的代码 bug，更难查）
删掉账号后页面变成**彻底空白**（连登录表单都没有）。用 headless Chrome
`--dump-dom` 抓渲染结果发现 `#content` 还是静态占位符
「正在加载参数规格…」，且 `typeof authRender === 'undefined'` ⇒
**app.js 没被加载**。
抓 `/static/app.js` 的响应头：**`HTTP/1.0 401`，body 51 字节的 JSON**。

根因在 `_gate()`：
```python
if not AUTH.is_configured():
    if path in ("/api/auth/status", "/api/auth/setup") \
            or path in _PUBLIC_STATIC:      # ★ 第二份白名单，只认文件名
        return True
```
它在「还没建账号」这一支里**自己又写了一遍白名单判断**，而那份只认
`_PUBLIC_STATIC` 里的文件名、**不认 `/static/` 前缀** ⇒ 首次使用时
`/static/app.js` 被 401 挡掉 ⇒ JS 加载不出来 ⇒ **连「创建账号」按钮都没有**。

**修法**：把静态资源放行提到最前面、且**只留 `_needs_auth` 一处定义**：
```python
if not self._needs_auth(path):   # 静态资源永远放行，与登没登录无关
    return True
if not AUTH.is_configured(): ...
```

#### 守卫
- `test_static_assets_are_public_before_an_account_exists` ——
  造一个「未建账号」的 store，断言 `/static/app.js` 等**放行**、
  且 `/api/spec` 仍**挡住**（别顺手把门全开）。
- `test_gate_does_not_redefine_the_whitelist` —— 断言 `_gate` 的**代码行**里
  不出现 `_PUBLIC_STATIC`。⚠️ 只看非注释行（注释里会提到它，第一版误报了）。
- 两个都注入回原 bug 验证过：报 `['/static/app.js', '/static/style.css']`。

#### 🧭 教训（最重要的一条）
**"看源码/看 HTTP 状态码"不等于"页面能用"。** 我连续两轮用 grep 和裸 socket
"验证通过"，而用户看到的是空白页。**能渲染就要渲染** ——
headless Chrome `--screenshot` / `--dump-dom` 是本机可用的（Chrome 在
`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`），
以后前端改动一律**先渲染再断言**。

### Q58：在新 Linux 机器上怎么初始化数据

用户问：「在新的linux机器上 我要怎么初始化数据」。

#### 交付

#### 先摸清的既有事实（不是猜的）
- 数据入口是 `python -m crypto_ls_research.data.{download,asset_class,funding_build}`
  （**没有** `data/__main__.py`，也没有 requirements/pyproject）。
- 依赖只有 6 个：**numpy / pandas / scipy / matplotlib / seaborn / pytest**；
  **没有交易所 SDK**（客户端是手写 HTTP）。
- `settings.CACHE_DIR` 是唯一来源，读 `CRYPTO_CACHE_DIR`，默认 `<repo>/data_cache`。
- `PLAN = {1h: full/2021-01-01, 15m: top40/2024-01-01, 5m: top8/2025-07-01}`；
  `TOP_N_FOR_BAR={top40:40, top8:8}`。本机候选池 **160** 只。

`candles=43,761 + funding=10,152 = 53,913 请求`，按 11 req/s ≈ **82 分钟**。
1h 单独 ≈ 56 分钟、27,072 请求。

#### 🔴 三个必须写进脚本的坑
1. **`--end` 默认是硬编码 `2026-09-26` 且为排他上界**。照默认跑会**静静少二十来天**
   而不报错 ⇒ 后续回测在旧数据上出结论。脚本改成显式
   `END="$(date -u -d tomorrow +%Y-%m-%d)"`（Linux 用 `-d`，macOS 用 `-v+1d`，两者都要给）。
2. **候选池从「今天的实时挂单」建** ⇒ 新机器重建的那份与本机**不是同一个宇宙**，

3. **`CRYPTO_CACHE_DIR` 一旦设了，下载器与读取器必须指同一个**，
   否则"下的和读的不是一份" → 表现为"明明下了却没有数据"。

#### asset_class 的真实分布（`--show` 实测）
`crypto 283 / equity 186 / commodity 8` —— OKX 的 USDT 永续里**六成**是代币化股票/商品
（NVDA/TSLA/QQQ/XAU/CL…）。不分类就等于悄悄换了研究标的，所以这步**不能省**。

#### 🔴 自写测试又被变异抓出假守卫（D1/D5 漏网）
我第一版 `_module_invocations()` **逐行**解析脚本，而真实调用是**续行**的：

修好后 6/6 有效变异全抓（改 flag 名、删 `--end`、写死旧默认、模块名拼错、
不存在的 flag、另一个模块的 flag）。
⚠️ 这与 Q55「从 `index.html` 抓 `src=`/`href=`」是同一类教训：
**解析文本做守卫时，先确认真的解析到了内容** —— 加一条

### Q59：新机器 `Errno 111 Connection refused` —— 代理端口写在默认值里

用户在新 Ubuntu 上报：
```
RuntimeError: GET /api/v5/public/instruments failed after 4:
  URLError: <urlopen error [Errno 111] Connection refused>
```
问「怎么改成7890代理」。

#### 根因：代理**已经是可配置的**，但默认值写死成开发机的端口
三个客户端都读**同一个**环境变量：
```python
DEFAULT_PROXY = os.environ.get("OKX_PROXY", "http://127.0.0.1:7897")
```
`okx_client.py:24` / `binance_client.py:48` / `okx_private.py:57`。
开发机代理在 **7897**，新机器在 **7890** ⇒ 请求还没出本机就被代理拒掉。

⇒ **不用改代码**，`export OKX_PROXY=http://127.0.0.1:7890` 即可。
实测（本机 7897 通）：`instruments('SWAP')` 返回 **509** 条、`tickers` 504 条。

#### 🔴 这个错为什么难查
`Errno 111 Connection refused`（Linux）/ `Errno 61`（macOS）**看不出是代理问题** ——
只像"网络不通"。而且四个客户端共用一条 import 时求值的常量，所以
**进程起来之后再 export 没用**（`DEFAULT_PROXY` 在模块导入时就定死了）。

#### 交付的改动
1. `init_linux.sh` **新增第 0b 步「代理体检」**（排在下载**之前**）：
   拿 `OKX_PROXY` 去 `socket.create_connection` 探活，三种结果分别处理：
   - 通 → `✓ 代理可达：host:port`
   - **不通 → 直接 exit 1**，并打印「三个客户端读同一个 `OKX_PROXY`、
     怎么 export、或者 `OKX_PROXY=` 直连、`ss -ltnp` 查端口」
   - 空 → 提示"走直连"但**不退出**（服务器上常需要）
2. `init_linux.sh` 顶部 `export OKX_PROXY="${OKX_PROXY-http://127.0.0.1:7897}"`
   —— 必须是 **export**，因为下载是子进程跑的。
3. `DEPLOY_LINUX.md` 增「🔴 代理：换机器必看」小节 + 手工版也补上那行。

#### 为什么能设空来直连
客户端里是 `if self.proxy:` 判断 ⇒ 空串 = 不加 ProxyHandler = 直连。
⚠️ 注意别写成 `os.environ.get("OKX_PROXY") or DEFAULT`（空串会被 falsy 掉）。

#### 守卫 `test_deploy_script.py`（11 条，新增 4 条 / 变异 4/4 全抓）
- 脚本必须 `export OKX_PROXY`（**export 而非赋值** —— 子进程要读）
- 代理体检必须排在 download **之前**
- **三个客户端读同一个变量名**（否则改端口要改三处，漏的那处只在换源/实盘时炸）
- `OKX_PROXY=''` ⇒ 得到空代理（→ 直连），不是回退到默认

### Q62：Linux 上回测 `-9`（SIGKILL）—— **2GB 机器跑全量宇宙被 OOM 杀**

#### 实测内存需求（154 只 × 50.7k bars 的 1h 宇宙）
| 阶段 | maxrss |
|---|---|
| 起进程 | 96 MB |
| `load_panels` 后 | **1236 MB** ← 一步吃掉 1.14GB |
| `run_backtest` 后 | **2193 MB** ← 峰值 |
| `compute_metrics` | 2193 MB |

1. **`_read_one(downcast=True)`**：读进来就把 float64 列降到 float32。
   单只 **3.25 MB → 1.83 MB（省 44%）**。
   ⚠️ 这**不改变数值** —— `wide()` 最后本来就 `astype("float32")`
   （旁边注释解释了 float32 的 ~1e-7 相对精度足够），这里只是把转换**提前**，
   让 float64 的峰值根本不出现。

4G swap 文件（`fallocate || dd`，后者在 overlayfs 上更可靠）：
```bash
sudo fallocate -l 4G /swapfile || sudo dd if=/dev/zero of=/swapfile bs=1M count=4096
sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

```

而宽表构造的瞬时峰值取决于分配器复用的时机。
⇒ 报内存数字要说清是"哪一步的 maxrss"，别当成稳定值。

#### 我写的守卫又差点假绿
`test_wide_one_pass_is_bit_identical` 里我用 `eval(...)` 解析子进程输出，
但打印的是 `RESULT True True`（**空格分隔，不是元组字面量**）⇒ SyntaxError。
而且**报错信息误导**：测试说"跑不动"，实际是内层脚本语法错。
⇒ 改成 `.split()` + `x == "True"`。
⚠️ 同类坑：**在测试里拼字符串代码**时，内层的语法错会被外层的
    `assert returncode == 0` 概括掉，看不出真因。

### Q65 续：**测试套件自己把机器 OOM 了**（137 且无任何失败信息）

现象：全量测试报 **`1 failed, 732 passed`**，失败的是我刚加的
`test_wide_one_pass_is_bit_identical` —— 但它**单跑通过**。

#### 定位过程
1. 单跑通过、整文件跑 137 ⇒ 典型的**测试间干扰**。
2. 二分：前半 14 条 1.34s 过；后半「不跑回测」的 7 条 0.20s 过。
3. 逐个测三条真跑回测的：
   - `test_a_failed_stage_...` → **单跑就 137**
   - `test_research_writes_a_log_file` → 单跑过，但**105 秒**
4. 排掉这三条，其余 25 条 **2.43 秒全过** ⇒ 真凶就是它们。

#### 🔴 两个真问题
**① `test_a_failed_stage_...` 用「不存在的因子名」制造失败 —— 代价是完整回测。**
因子名校验发生在 `run_backtest` 里面 ⇒ 走到那里说明**面板已全加载**（1.8GB）。
改成**不存在的 stage 名**（在调度循环里 `fn is None` 就发现）：
**137 → 1.07 秒通过**。

**② `test_research_writes_a_log_file` 跑全量（154 只）。**
它要验证的只是「日志会落盘」—— **与宇宙大小无关**。
加 `--max-insts 12`：**105 秒 → 9 秒**。

#### 修完后
`test_deploy_script.py` 整文件：**137 崩溃 → 28 passed in 63s**。

#### ⚠️ 教训（值得记）
- **`pytest` 是一个进程跑到底**：测试里起的子进程退出后，**主进程的常驻不退还**。
  于是"每条单独都过"的测试，合起来能把机器吃爆。
- **`退出码 137` 在 pytest 里表现为「套件突然没了、没有任何失败信息」** ——
  极难查。所以**重测试要主动缩小输入**，别图省事用全量。
- **在测试里"制造失败"要挑最便宜的那条路径**：我这轮选错了输入，
  为了测一个 `sys.exit(1)` 付了一次完整回测。
