## 保证金模式审计（用户：「是不是要强制为逐仓 不然一个爆了全仓爆了」）

**结论：对**独立方向性**的账本这个直觉对；对这个**对冲过**的账本是**反的** ——
强制逐仓把爆仓距离从 200%+ 缩到 30% 以内，并在强平那一刻**把对冲拆掉**。**

### 一条不等式就是全部答案
- 逐仓每条腿 `1/L − mmr`：`L=3` → **32.83%**，`L=5` → **19.50%**，`L=100` → **0.50%**。
- 全仓 `(1 − mmr·G)/G`：`G=0.4458` → **223.80%**，`G=1.0` → **99.50%**。
- 任意 `L≥1, G≤1` 下 **全仓 ≥ 逐仓**（守卫在 9×5 网格上逐点断言）。
- **对冲腿的浮盈躺在另一个保证金桶里，救不了另一条腿**。本账本净/毛 ~0.08，市场 −20% 时
  账户净亏 ~1.6% 净值 —— **账户没事，逐仓的每条多头腿都会死**；一条腿强平后**对冲断了**，
  剩下的是**裸方向仓**。

## 逐仓杠杆能不能统一设成 3×（用户：「为什么逐仓模式 倍数会变呢 能不能统一设置为3X啊」，Q38）

### 先纠正前提："逐仓倍数会变"不是"模式"在变

杠杆是**账户级配置**，键 `(instId, mgnMode, posSide)` —— **每合约 × 每模式 × 每方向一个格子**。
`leverage-info` 返回 **两条**记录（long/short），这就是"逐方向"的直接证据。全账户实测：
`cross` 全 **3×**、`isolated` 全 **3×**，**唯一例外 `BTC-USDT-SWAP isolated = 100×`**（= 其 `max_lever`）。
⇒ 切模式时"倍数变了"只是**读了另一个格子**。

### 能改 —— 但四个坑（都是实测）

| 坑 | 证据 |
|---|---|
| `mgnMode=isolated` **必须带 `posSide`** | 不带 → **HTTP 400**；带 `posSide=long` → 200 |
| `batch-set-leverage` **不存在** | → **404**；数组 body 打 `set-leverage` → 400 |
| 一次只改**一个方向** | 设 long 不动 short ⇒ **每合约两次** |
| **回读有几十秒延迟** | 连发 set 4/3/2，三次回读都是 **10**；45s 后才变成 **2** |

### ⚠️ 核心：改配置 ≠ 改持仓

干净腿对照（NEAR isolated long，$350，**从未被碰过**）：

```
before (clean)   config=3  pos.lever=3  margin=116.906  liqPx=3.317332  距离=32.44%
after 3→5 +65s   config=5  pos.lever=5  margin=116.906  liqPx=3.317332  距离=32.53%
                 ^^^^^^^^^^             ^^^^^^^^^^^^^^  ^^^^^^^^^^^^^^
```

## 控制台的三个可用性缺陷（用户：「删除会报错 / 交易台要显示小数 / 现在的脚本不能用」，Q39）

三个**互不相关**的毛病，我一开始想把前两个当同一个 bug 查，差点查错方向。分开后各自都能一步定根因。

### ① `删除失败：Unexpected token '<', "<!DOCTYPE "...` —— 是**旧进程**，不是删除逻辑

用户看到的是**前端报的解析错误**，根因在**后端根本没实现这个方法**。

- 裸 socket 打正在跑的那个控制台（PID **9982**）：
  `DELETE /api/runs/__no_such_run__` → `HTTP/1.0 501 Unsupported method ('DELETE')`
  + `Content-Type: text/html;charset=utf-8` + body 以 `<!DOCTYPE HTML>` 开头。
- 于是前端 `resp.json()` 抛 `Unexpected token '<'`，**真实状态码 501 被这句话完全藏住**。
- 时间线对上了：`do_DELETE` 是 **09-30 00:46**（commit `321a31d`）进的 `webapp/server.py`，
  而那个进程 **09-29 18:51** 就起来了 ⇒ **改动在磁盘上，但没进进程**。
  （`do_GET` 全正常，所以"控制台能打开"这件事**完全不能**证明它是新的。）

修法**两头都要**：
- `webapp/server.py` 加 `Handler.send_error()` 覆盖 —— **`/api/` 下的任何错误一律回 JSON**
  （静态页仍走 HTML，这是故意的，有反向断言钉住）。
- `webapp/static/app.js::deleteRun` 不再盲 `resp.json()`：先 `resp.text()` 再自己 `JSON.parse`，
  并**把 HTTP 501 单独识别**出来提示「服务端不支持 DELETE —— 控制台多半没重启」。
  （只修后端的话，下次换个方法还是会报同一句天书。）

**已重启**（9982 → 30218 → 30584）并复验：`DELETE /api/runs/__no_such_run__` → JSON 404、
`PUT /api/whatever` → JSON 501、非 `/api/` 路径仍 HTML。**用户那边按钮现在能用了。**

### ② 交易台金额显示小数 —— `fmt.dol` 用了 `Math.round`

`$2,586.98` 被渲染成 `$2,587`。交易台的净值 / 未实现盈亏 / 持仓名义 / 订单名义**全走这一个函数**。

改法：默认 `minimumFractionDigits: 2, maximumFractionDigits: 2`；**唯一例外**是
`0 < |v| < 0.005` 时用 `toPrecision(3)` —— 否则 `$0.004` 会显示成 `$0.00`，
**"这是零"比"没小数"更误导**。

**顺手修了同类的第二个毛病**：原来直接拼 `'$' + v.toLocaleString()`，负数渲染成
**`$-1,234.50`**（币种符号和负号打架，看着像坏了）。改成先取绝对值排版、再补符号
（`n < 0 ? '-$' : '$'`），`-0` 仍是 `$0.00`。
⚠️ 这个负号位置**原本被冒烟测试钉着**（`'$-1,234.50'`）—— 所以"测试全绿"**不等于**"显示是对的"：
断言当时是把现状写进去了，不是把意图写进去了。已连断言一起改。
变异验证：改回 `'$' + (n < 0 ? '-' : '')` ⇒ **2 条红**，还原 240 ok / 0 FAIL，sha 双向核对。

**顺带量到一条运维事实**：`GET /static/app.js` 回的字节与磁盘**逐位相同**（174,031 B）
⇒ 静态文件是**每请求读盘**，改 `app.js` **不用重启**；只有改 `server.py` 才需要。
（我原来那条"改 `webapp/` 必须重启"写得太宽，已收窄。）

### ③ `START_AUTO_TRADER_DEMO.command` 报 `No module named 'numpy'`

用户贴的栈：`使用解释器: /opt/homebrew/bin/python3` → `import numpy` 失败。

- 候选表里写的是 `~/.workbuddy/binaries/python/envs/default/bin/python3`，
  **真路径是 `~/.workbuddy-ai/binaries/...`（少了 `-ai`）** ⇒ 这条永远命中不了。
- 而筛选条件是「**文件可执行**」，不是「**有依赖**」⇒ 一路回退到 `/opt/homebrew/bin/python3`，
  那个解释器**没有 numpy**。报错停在 `import numpy`，**指不到"选错解释器"这个根因**。

实测三个解释器：managed venv **numpy 2.5.3 / pandas 3.0.6**（要的）；
`/opt/homebrew/bin/python3` **无 numpy**；`/usr/bin/python3` numpy 2.0.2 / pandas 2.3.3（可用）。

改法：候选表路径改对 + 判定改成 `"$cand" -c 'import numpy, pandas'`；显式传的 `PY` 也要过同一道检查，
不过就**带原因回退**（`PY_TRIED` 逐个列出试过谁、为什么不行）。三个 `.command` 都改了、都 `chmod +x`。
验证：自动发现选中 managed venv；故意传一个坏 `PY` 能正确回退。

## 换币安数据跑回测（用户：「你试一下用币安数据跑回测看下」，Q40）

### 实验设计：只动一个变量

### 过程中修掉的三个真问题

1. **`binance_client.py` 原来只有资金费，没有 K 线。** 新增 `klines_range()`，

   必须是价格量级。**写反了不报错**，只会让 vwap 变成 ~价格²。
2. **比价格一致性前必须先除掉固定面值因子。** 币安有 `1000PEPEUSDT` 这类 1000 倍计价合约，
   **价格水平比天然是 ~1000**。第一版没除，p99 直接报 **999.36** —— 差点当成
   "两边价格差 999 倍"报出去。收益是尺度无关的，所以只影响水平比较。
3. **选择性扫描第一版被 OOM 杀掉（exit 137）**：同时持有两个场所的 panel
