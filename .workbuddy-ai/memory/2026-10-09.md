### Q47：页面「持仓名义 $227」vs OKX「保证金占用 $246」——差在哪（2026-10-09）

用户报：页面毛敞口 $227.10 (0.638×)，但 OKX 里保证金占用 **246**。**差 ~$19（8.4%）。**

**结论：两个数说的是两件事，都不是错的；但页面的标签会误导。**

**① 差异的机理：逐仓保证金锚在开仓名义，只涨不跌。**
逐条读 `/account/positions` 的 `margin` 与 `notionalUsd`（21 条腿全部 1×）：

- **亏损腿（upl<0）**：`margin = notionalUsd − upl` = **开仓时的名义**，逐条残差 **< $0.07**。
- **盈利腿（upl>0）**：`margin ≈ notionalUsd`（**高于**当前名义），即盈利**不释放**保证金。
- 汇总：名义 **226.94**、margin **241.81**（≈用户看到的 246）、差 **+14.88**。

**② 各腿的 margin/名义 倍数从 0.98 到 1.26 不等**（ONDO 0.98、ETH 1.004、USELESS 1.264）。
差异的主因是**未实现亏损**（亏损腿的保证金被吃掉）与**入场价 vs 标记价**的偏离。
⚠️ 我**没有**找到一个在全部 21 条腿上残差都 < $0.08 的闭式解 ——
`名义−min(upl,0)` 最大残差 $2.07（UNI/ARB 两条盈利腿偏离最大）。
**所以：机理确定（保证金锚开仓名义、亏损吃掉它、盈利不释放），但精确公式未完全钉死。**
再往下一般化会变成"用结果拟合结果"。**要精确复现请直接读 `margin` 字段，别自己算。**

**③ 这不是 bug —— 是页面标签的问题。**
`margin` 与 `notionalUsd` 是**两个不同的量**：
| 量 | 含义 | 当前值 |
|---|---|---|
| 名义（notionalUsd） | 按**标记价**折算的风险敞口 | 226.94 |
| 保证金（margin） | 逐仓账户里**被锁住**的钱 | 241.81 |

页面写「持仓名义 0.638×」是对的（226.94/356.21 = 0.637）；但它旁边**没有**保证金占用这个数，
所以用户只能在 OKX 里看，于是两个数看起来像矛盾。

**④ 真正的后续问题：margin/NAV = 67.9%。**
$241.81 锁在保证金里，NAV 只有 $356.21 ⇒ **可用余额约 $114**。
下次调仓要下单名义 ~$68（历史 15–16 笔、turnover 19–21%）——
**逐仓下开新仓要占用新的保证金**（锚开仓名义，不是差额）⇒ 如果目标腿增加，
可用余额可能不够。这是一个**容量/资金约束**，不是计价 bug。
⚠️ 待办：确认逐仓下"从 A 腿换到 B 腿"是否能靠平 A 释放的保证金开 B（同一次调仓内的时序）。

### Q47 补：**246 就是 `isoEq`，交易所自己的字段** —— 不需要拟合
`/api/v5/account/balance?ccy=USDT` 的原始字段（真实值）：

| 字段 | 值 | 含义 |
|---|---|---|
| `eq` / `totalEq` | **356.24 / 355.91** | 账户总权益（≈ 页面 NAV 356） |
| `isoEq` | **246.22** | **逐仓占用的保证金余额** ← **用户看到的 246** |
| `imr` / `mmr` | **0 / 0** | 全仓的初始/维持保证金（**全仓没持仓，所以是 0**） |
| `availBal` / `availEq` | **109.79** | **可用余额** = 356.24 − 246.22 ≈ 110 |
| `frozenBal` | 246.45 | 冻结（含 isoUpl 4.64） |
| `upl` / `isoUpl` | **+4.64** | 未实现盈亏（**净盈利**） |

**决定性事实**：
1. **246 是逐仓锁定的钱（`isoEq`），226.94 是按标记价的风险敞口（Σ notionalUsd）。**
   两者**不是同一个量**，页面和 OKX 都没错。
2. `imr = mmr = 0` 证实**全部 21 条腿都是逐仓**（`MARGIN_MODE=isolated`），
   所以全仓保证金为 0 —— 这与 Q36 的"逐仓每腿用自己的保证金"一致。
3. **可用余额只有 109.79**（占权益 30.8%）。这是真正的可操作约束。
4. 我先前试图找 `margin` 的闭式解没成功是对的 —— **它不需要拟合，读 `isoEq`/`margin` 就是权威值**。
   教训：**先找官方字段，再考虑建模**（Q33 的"自写估计量必须先验证"同一类）。

**⚠️ 操作含义（待确认）**：下次调仓要下单名义 ≈$68（历史 15–16 笔）。
逐仓下开新仓要**新占**保证金（锚开仓名义）⇒ $109.79 的可用余额是否够，
取决于"平掉旧腿释放的保证金能否在同一轮里给新腿用"。
**这是需要实测的时序问题，不能假设。**
