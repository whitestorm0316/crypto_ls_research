## Q74 — 用户报「#live 一片空白」+ 侧栏改回常驻

### 症状与定位

截图 URL 是 `127.0.0.1:8790/#live`，顶栏/胶囊都正常、`#content` 全空、**无任何报错**。
先排除 JS 抛错（`window.onerror` 会插 banner，页面上没有），再把截图切块放大：
内容区颜色 `#F2F4F8`（= `--bg`）⇒ 真的没内容；左边缘那条 10px 宽的浅绿竖条
是「当前参数 = 已验收最优配置」横幅（`--ok-soft`）被**挤成一条缝**。

根因在 CSS：

```css
body.sidecollapsed .main { grid-template-columns: 0 1fr; }
body.sidecollapsed .side { display: none; }   /* ← 这句让 side 退出栅格 */
```

`display:none` 的元素**不参与栅格布局**，于是 `.content` 变成第一个栅格项、
被自动放进第 1 列 —— 就是那个 `0`。实测 `.content` 只有 **40px**（padding），
而 `getComputedStyle(.main).gridTemplateColumns` 仍返回 `0px 1280px`，**看着正常**。
交易台 `#live` 当时默认收起侧栏 ⇒ 一进这页就是空白。

修法：`body.sidecollapsed .main { grid-template-columns: 1fr; }`（单列）。
实测 `content` 40 → 1280px；12 种（4 状态 × 3 tab）组合全部 ≥ 863px。

### 我上一轮为什么没抓到

P0-3 的验收只量了 `gridTemplateColumns` 这个**字符串**（`0px 1280px`），没量元素
真实宽度。同一类错误的第三次变体：判据看着通过、用户看到空白页。
⇒ **量 `getBoundingClientRect().width`，别量样式字符串。**

### 用户随后要求：侧栏改回常驻

「左边的 tab 跟之前一样保持常驻」。删掉 `syncSideForTab()`（按 tab 自动收起）
与它的调用点；`bindSideToggle()` 改成 `setSide(sidePref() === '1')` ——
没点过就是展开，**换 tab 不改布局**。开关保留（临时多看一列表格），点过才记 localStorage。
实测：进 `#live` 侧栏 412px / 内容 863px；依次点 交易记录→回测结果→交易台，侧栏一直是 412px。

### 守卫

`test_shell_state.py` 从 10 条加到 12 条，其中 3 条是新口径：

  `body.X .side { display:none }`，要求 `body.X .main` 是**单列**（抓模式，不抓某一行）；
- `test_main_never_uses_a_zero_width_first_track`：禁止 `.main` 出现 `0 1fr`；

## Q75 — 弹层「二次确认点了没用」

用户报：删除的二次确认弹出来了，点「删除」什么都不发生，也不报错。

### 根因：选择器和标记对不上

```js
btn({ data: { uimOk: '1' } })      →  <button data-uimOk="1">   （原样拼键名）
HTML 解析器                         →  data-uimok               （属性名小写）
modal 里 querySelector('[data-uim-ok]')  →  null
```

`okBtn` / `cancelBtn` 都是 null ⇒ **两个按钮的事件一个都没绑上**；只有
× / Esc / 点背景能关（它们直接调 `finish`）。受影响的不止删除：取消回测、
偏离最优继续跑、补齐宇宙、快捷键帮助全是同一个 `ui.modal` —— 全都点不动。

修法：`btn()` 里把 data 的键转 kebab（`kebab = k => k.replace(/[A-Z]/g, c => '-'+c.toLowerCase())`）。
`data: { uimOk }` → `data-uim-ok`，`data: { runId }` → `data-run-id`。

### 为什么所有守卫都没抓到（这条最值钱）

- `test_run_cancel_ui.py` / `test_three_states.py` 的行为测试把 `ui.modal`
  **替换成 stub**（`ui.modal = async () => true`）⇒ 只证明了「拿到 true 之后
  干什么」，从没证明「点按钮能不能拿到 true」。
- `test_ui_components.py` 只看渲染出的字符串配平 / 无脏文本，不看事件绑定。
⇒ **行为测试不许把被测组件本身 stub 掉。** 交互层要用真 DOM。

### 新守卫 `test_modal_click.py`（7 条，用 jsdom）

托管 node 的 `~/.workbuddy-ai/binaries/node/workspace/node_modules` 里**有 jsdom**
（`NODE_PATH` 指过去即可）。做法：`new JSDOM(html, {runScripts:'outside-only'})` +
`window.eval(ui.js + ';window.__ui = ui;')` ⇒ `innerHTML` 走真解析器，然后 `.click()`。

注意两个坑：
- `ui.js` 首行 `'use strict'` ⇒ eval 出来是**独立作用域**，顶层 `const ui` 不会
  落到 window 上，必须在**同一段脚本**里显式 `window.__ui = ui`（老坑的新变体）；
- 要跑 app.js 时必须把 `ui.js` 和 `app.js` **拼成一段**再 eval，否则两个严格
  eval 各自作用域，`app.js` 看不见 `ui`（浏览器里是同一全局词法环境）。

覆盖：确认/取消/×/Esc/点背景 五条关闭路径、`requirePhrase` 闸门（没输入点不动、
输错不放行、输对返回短语）、`hideCancel` 只留一个按钮、`btn` 键必须 kebab、
端到端 `deleteRun()` → 点「删除」→ 真的发 `DELETE /api/runs/<id>`。

6 个变异全部被抓（data 键不转 kebab、确认按钮不绑事件、取消按钮不绑事件、
requirePhrase 闸门失效、hideCancel 失效、deleteRun 改回原生 confirm）。

⚠️ 变异脚本被 **OOM(SIGKILL/137)** 打断过一次：每次 jsdom 都要重载 219KB 的
app.js，连跑 6 次 pytest 会顶爆内存，而且 `finally` 没执行 ⇒ **文件里留着变异**。
以后变异脚本要么一个一个跑，要么先备份再改、跑完用 sha 校验还原。

## Q76 运行记录页三件事（2026-11-09 下午）

用户一口气提了三个：「运行完回撤后核心指标没显示、要刷新才出现」「加批量删除按钮」
「加个按钮重跑 v5_1d_all5 基线」。

### ① 指标不刷新 —— 根因是**详情快照过期**

`pollRuns()` 每 2.5s 拉一次列表，但 `S.detail` 是**任务还在 running 时**抓的那一份，
里面没有 `result` / `metrics`。旧代码只把 `S.detail.status` 改成新状态就重绘 ⇒
任务跑完了，指标位全是「—」，必须手动刷新（刷新会重新 `GET /api/runs/<id>`）。

修法：状态**跃迁到终态的那一刻**重拉一次详情。

```js
const RUN_TERMINAL = new Set(['done', 'partial', 'failed', 'cancelled']);
if (RUN_TERMINAL.has(cur.status) && S.detail.status !== cur.status) {
  await reloadDetail(S.selected);      // 只在这一刻拉，否则每 2.5s 打一次接口
} else {
  S.detail.status = cur.status;
}
```

`reloadDetail()` 要**保住 `_log`**（日志面板是自己增量攒的，不是详情接口给的），
否则刷新详情会把用户正在看的日志清空。

### ② 批量删除 —— 不新开接口，逐条复用单条 DELETE

后端 `_delete_run` 已经有一整套安全规则，重写一遍必然走样：
- `queued` / `running` 回 **409**；
- 最优 tag 的产物**保留**，只删列表项 + 日志；
- 产物目录 **rename 进 `artifacts/.trash/`**，不是 `shutil.rmtree`（宿主机有 safe-delete
  守卫，会直接 `SystemExit`）。

所以前端就循环发 `DELETE /api/runs/<id>`，失败的单条记下来一起报。

两个「看着能跑其实会坏」的点：
- **勾选态必须放 `S.picked`**，不能放 DOM —— `pollRuns()` 每 2.5s 整块重建列表，放 DOM
  里一刷新就丢；
- `.runs` 是 6 列 grid，批量模式多一个勾选框 ⇒ **列数必须 +1**，否则第 7 个子元素
  换到下一行、整列表错位。

`bulkPicked()` 会把未结束的任务过滤掉，所以「已选 N 条」不会虚高，删除按钮的 disabled
也跟着它走。`syncBulkBar()` 只改两个节点，勾选时不做整块重绘。

### ③ 重跑基线 —— 三样东西都不能从面板拿

- **tag**：从 `/api/spec` 的 `optimal_tag` 取。前端写死过一次（`v3` → `v4_1d` →
  `v5_1d_all5`），每次换口径都要改前端。
- **阶段**：取**最宽的那个 bundle**（`full`，15 段）。面板上当前选的可能是「快速回测」，
  拿它去跑就凑不出 16 个门禁。
- **参数**：从 spec 的 `OPTIMAL_CLI` 派生，不是面板上的输入框。

弹窗里必须写清「会覆盖 `artifacts/<tag>/`」，因为这是真的会覆盖。
