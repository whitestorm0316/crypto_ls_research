## Q77 目标年化波动 30% → 50%（换口径）

用户要求：「修改项目 目标年化波动为50% 自动允许那里也一样」。

### 改了什么

| 位置 | 改动 | 为什么 |
|---|---|---|
| `config/settings.py::RiskConfig.target_vol_annual` | 0.30 → **0.50** | 唯一来源；回测、实盘、自动交易都从这里取 |
| `webapp/spec.py` 面板「目标年化波动」default | 0.30 → **0.50** | 面板默认必须和 dataclass 一致，否则「恢复默认」会把 50% 改回 30% 再当 override 发出去 |
| `execution/limits.py::LiveLimits.max_gross_frac` | 1.0 → **1.5** | 50% 目标下实际账面 p95 = 1.21×，1.0 会拒掉约 1/5 的调仓 |
| `artifacts/live/live/limits.json` | `max_gross_frac` 1 → 1.5 | 实盘读的是这份保存值，不改等于没改 |

**自动交易那条路不用单独改**：`DEFAULT_SIGNAL["overrides"]` 只有因子集 / 单名上限 /
换手预算三个键，**不带任何 `risk.*`**，所以 `LiveEngine` / `AutoTrader` / 自动调度全部
继承 dataclass 默认值。实测 `build_config(...)` 出来就是 0.5。

### 🔴 我这一轮说错过一个数

我说「80% 的调仓会被 1.0× 闸门 block」——**错的**。80% 是**原始目标**（未过换手预算）
超 1.0 的比例，而 `check_plan` 检查的是 `plan.realised_gross`，即**本次调仓完成后的账面**，
每天最多只能移动 20% NAV。按基线实测只有 **19.7%** 的时间超 1.0×（30% 口径本来也有 4.9%）。
教训：报「会被闸门拦掉多少」必须用闸门真正读的那个量，不能拿上游的目标值代替。

### `failure_attribution` 的 5 个窗口

基线重建后那 5 个 `dd_stated` 全部对不上（W1 −0.1331 vs 实际 −0.1553 …）。处理：

- 深度按新基线重测：−0.1553 / −0.1407 / −0.1315 / −0.1117 / −0.1224；30% 原值写进注释。
- 🔴 **W5 的谷底后移 7 天**（2022-09-21 → 2022-09-28），落到原窗口外。不挪窗口的话，
  窗口里只剩一个 1 根 bar 的噪声段（−0.0002），会把一次 −12% 的回撤写成 −0.02%。
  所以 `W5` 的 end 改成 2022-09-28，并在 docstring 里点名「这是唯一被改过的边界」。
- 🔴 **`match_windows` 原来取 `hit.iloc[0]`（按时间第一条）**，不是最深那条。窗口边界是
  用户给的、谷底是市场给的，两者不必重合 ⇒ 改成 `hit.loc[hit["depth"].idxmin()]`。
  这个 bug 在 30% 口径下恰好没暴露（W2/W4 的大段恰好排在最前）。

### 顺带被基线重建炸出来的一条老缺陷

`test_short_squeeze::test_short_loss_decomposition_sums_to_the_short_pnl` 变红：REST 桶里
三项之和比 `short_pnl` 少 0.00619。查下来是**一个 bar**（2021-05-20 02:00）的 `pool_mean` /
`excess_select` / `excess_weight` 全是 NaN，而 `short_pnl` 是有限值：

- 三项只在 `isfinite` 的点上求和，`short_pnl` 是全量求和 ⇒ 差额静默消失。
- 这正是 Q42 那条老毛病「算不出来被静默丢掉」的第四次出现。
- 修法：`short_book_table` 增加 `n_unattributed` / `short_pnl_unattributed` 两列，
  测试的恒等式带上这一项，并断言「有残差就必须有计数」。
