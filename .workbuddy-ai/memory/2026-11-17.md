## Q78 新增「标的池」页（当前池子 + 流动性强弱）

用户问：「可以加一个页面显示当前池子 以及当前流动性强弱等数据吗」。
做成了第 4 个 tab（`#universe`），数据来自新的 `GET /api/universe`。

### 口径：`adv` 是「每根 bar 的均成交额」，不是日额

这是整个页面最容易做错的地方，也是我一开始差点写错的地方。

`factors/engine.py:44`：

```python
adv_bars = max(2, int(round(ucfg.liq_window_days * bars_per_day)))
adv = amount.rolling(adv_bars, min_periods=max(2, adv_bars // 4)).mean()
```

`amount` 是**单根 bar 的成交额**，所以 `adv` 是「每 bar 平均成交额」。1h 上
`min_avg_amount_usd = 3e6` 等价于「每小时 $3M ≈ 每天 $72M」。实测差别：

| 口径 | 过线数量 |
|---|---|
| 每 bar ≥ 3M（引擎口径） | **16 只**（crypto 范围） |
| 折日 ≥ 3M | 196 只 |

差 12 倍。面板上那句「30 日成交额门槛（USD）」按字面读会被理解成日额，所以页面上
**同时印两个数**：「$3.00M/每根 1h bar ≈ $72.00M/天」。

同理 `risk.adv_cap_delta` 的预算 = `adv × 5%`（每 bar 的 adv），写成
`adv_day × 5%` 会大 24 倍且不报错。

### 页面结构

- 概览：在池只数 / 池内中位日成交额 / 池内合计 / 24h 放量中位。
- 表格：`# / 标的 / 类别 / 30日均(每1h) / 折日 / 最近24h / 放量 / 5%上限 / 最小下单`。
- 「放量」= 最近 24h 实际成交额 ÷ 折日均值 − 1，用**以 0 为中心的条形**表示
  （右=放量蓝、左=缩量琥珀）。**不用涨跌色** —— 成交额放大 ≠ 价格上涨。
- 默认只显示在池的；「显示全部 199 只」把剔除行也列出来，并标原因
  （成交额不足 / 上市太短 / 排名截断 / 无行情）。
- 持仓行标 `持仓` chip（读 `Store(mode).read_state()["positions"]`，读不到就当没有）。

### 四个实现上的坑

1. **加第 4 个 tab 必须改 4 条 CSS 规则。** `.resultOnly/.tradesOnly/.liveOnly` 那组
   是「默认 block、两个 tab 下 none、每个 tab 各 4 条」的结构。漏一条的表现不是报错，
   是「切到新页面，旧的也还挂着」。
2. **`#uniRoot` 必须每次 `renderContent` 从 `S.uni` 重绘。** `pollRuns()` 每 2.5s 重建
   整块 `#content`，少了那一行页面每 2.5 秒退回骨架（不报错）。和交易台同一个坑。
3. **宽表要自己滚。** 10 列的表配 `.uniwrap { overflow-x: auto }`；否则
   `1fr` 是 `minmax(auto,1fr)`，宽内容会把 `.content` 撑破（P1 遗留的窄视口溢出）。
   实测把面板压到 620px：wrapper 590/789 内部滚动，`.content` 宽度不变。
4. **`_read_one` 的「空文件」≠「文件缺失」。** 一开始两者都返回 None，于是「盘上有这只、
   但一行行情都没有」的标的直接从表里消失 —— 用户会以为筛选条件写错了。改成：文件缺失
   返 None（跳过），空文件返空表（留一行 `no_data`）。
